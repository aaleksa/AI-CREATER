## 1. Суть продукту

Auteur — не копія Canva і не відеоредактор рівня CapCut.

Це проста студія, у якій людина **не повинна знати, як працюють 5–6 різних AI-сервісів**. Вона не вибирає модель, prompt, resolution чи voice engine.

Головна обіцянка:

> Tell us what you want to create. We’ll do the rest.

Користувач каже:

> «Мені потрібна реклама мого салону краси для Instagram»

Система сама вирішує: який AI, яка картинка, який голос, який формат, які субтитри, який стиль бренду — і **віддає файл, який можна викласти**.

Обіцянка не виконується, поки на виході немає реального відеофайлу. Прев’ю в браузері (розкадровка) — проміжний стан коду, не прийнятий MVP.

### 1.1 Для кого (v1 — одна персона)

**v1 заточений тільки під власника малого бізнесу:** кав’ярня, салон краси, фітнес-студія, кабінет — людина, якій потрібен регулярний Reel / TikTok у своєму бренді, без оператора й без стеку нейромереж.

Brand Kit — головна фіча саме для цієї персони: consistency вигляду й тону.

**Не персони MVP** (прибрати з пріоритетів, не проектувати під них екрани):

| Кого не беремо в v1 | Чому | Коли |
| --- | --- | --- |
| Сольний креатор | хоче «свій голос», особистість, авторський стиль — інший продукт | після утримання малого бізнесу |
| Агентство | хоче batch, кілька клієнтів, варіанти A/B, командний доступ | Business / окремий трек |
| Дитячий мульт / «свій герой-кролик» | сценарій на 2–5 хв, 8–10 сцен, діалоги, Leonardo / Canva / ElevenLabs / CapCut — інший продукт | ніколи як ядро v1; не плутати з рухом у Reel (§12.1) |

Це свідомо звужує roadmap: **batch-генерація, мультиакаунт клієнтів, «мій голос як інфлюенсер», дитячий мультконвеєр — не робити зараз.**

### 1.2 Що вважається успіхом MVP

Користувач (власник малого бізнесу) заходить → обирає **Коротке відео** → пише одне речення → проходить 6 кроків → **отримує готовий 30-секундний вертикальний відеофайл (mp4)** для Instagram або TikTok → credits списані → в логах є собівартість кожного AI-виклику.

«Студійний прев’ю без файлу» **не** є успіхом MVP. Це генератор сторібордів. Поки немає TTS + базового рендеру — продукт не показувати зовнішнім користувачам як «готовий Reel».

Якщо цим реально користуються повторно (див. критерії в §11) — далі пости, реклама, YouTube.

### 1.3 Рів (чому це не ще один шар над OpenAI)

Саме по собі «система вибирає модель / голос / стиль» — уже роблять HeyGen, Fliki, Predis. Це **гігієна**, не рів. Копіюється за тиждень.

Справжній рів Auteur — три речі, які треба закладати в продукт, не лише в голові:

1. **Brand Kit, який навчається.** Не тільки hex і тон у формі. Після 2–3 роликів система дивиться попередні Reels цього бізнесу (хуки, темп, слова, кадри, що користувач не відхилив) і підкручує наступні. Статичні кольори — v1-мінімум; навчання з історії — обов’язковий напрям одразу після першого mp4, інакше Kit = таблиця з CSS.
2. **Вузька ніша малого бізнесу, не генераліст.** Готові сценарні каркаси під салони, кав’ярні, фітнес (не маркетплейс на 100 шаблонів, а 3 вертикалі). Генералістські конкуренти цього не роблять добре.
3. **Прозора собівартість** — у БД (`ai_generations`). На беті таблицю викликів **ховаємо** (`SHOW_AI_COST_LOG=false` у Billing): це внутрішня цифра, не екран салону. API `/billing/credits` усе одно віддає generations. Показати знову — коли бета попросить, не зараз.

Без цих трьох пунктів продукт — прошарок над чужим API.

### 1.4 Зафіксовані рішення MVP (перший крок, не «перед демо»)

Оцінка термінів і собівартості **невалідна**, поки TTS і рендерер «на вибір». Нижче — прийнятий стек. §15 більше не містить цих пунктів як відкритих.

| Рішення | Вибір | Чому саме так |
| --- | --- | --- |
| **TTS** | OpenAI `tts-1`, голос `nova`, той самий `OPENAI_API_KEY`. Dev без ключа: macOS `say`. Тихий wav — тільки локальний fallback, **не бета і не демо**. | Один уже наявний ключ; не тягнемо другого вендора в MVP. |
| **Рендерер** | **ffmpeg** (`ffmpeg-static`): 1080×1920, H.264 + AAC, кадри (або колір бренду) + голос + SRT. Без Ken Burns, transitions, Remotion. Рух у кадрі — **після бети**, §12.1 (Kling), не в MVP. | Найкоротший шлях до відтворюваного файлу. Remotion — ні. «Реальний рух» ≠ Ken Burns. |
| **Captions ↔ аудіо** | **Scene-level**, не word-level. Cues зі скрипта, пропорційно підігнані під фактичну тривалість `voice.mp3`. | OpenAI TTS **не віддає word timestamps**. Word-level — окремий API (ElevenLabs alignment) **після бети**, якщо сцена-рівень ламає читабельність. |
| **Де файл** | `backend/data/media/{projectId}/voice.mp3` і `reel.mp4`. Не системний tmp. S3 — не MVP. | Передбачуваний шлях, gitignore `data/`. |
| **TTL / ліміт** | **Диференційовано.** Проміжні `voice.mp3` / кадри / `.srt` — **7 днів**. Готовий `reel.mp4` — **90 днів** (або до S3). Ліміт архіву **залежить від плану** (§5.3), не єдине «10 для всіх». Перед витісненням — попередження в UI, не тихе видалення. На екрані Create: «завантажте зараз». | mp4 дешевший у зберіганні і дорожчий у регенерації (55 cr). 7 днів на все = повторна оплата за вже куплений ролик. |
| **Регенерація** | Повтор `POST` без прапора — **безкоштовний і не викликає AI** (залишити як є). `{ "regenerate": true }` — платно. **Перші 3 спроби** (1 Make + 2 retry) за ціною кроку; далі можна ще, **за 2× credits**, з confirm. Credits до виклику провайдера; якщо AI вже пішов — не повертаються. | Користувач вибирає: лишити / заплатити ще раз. Жорсткий 429 після 3 спроб убиває вибір і retention. 2× криє вендора, коли credits FROZEN. |
| **Idempotency** | Заголовок `Idempotency-Key` (або тіло) на `POST /steps/:step`. Повтор того самого ключа після success — 0 credits, без AI. Паралельний той самий крок — 409. | Подвійний клік / retry браузера не має списувати Voice двічі. |

ElevenLabs як дефолт — **відхилено для MVP**. Перегляд після бети, якщо (а) якість `tts-1` ріже retention або (б) scene-level субтитри неприйнятні.

### 1.5 Закрита бета ≠ публічний запуск

§1.2 і §4.1 забороняють показувати продукт зовні як «готовий Reel» без mp4 — це про репутацію. Собівартість (§9.0) і retention (§11.11) потребують **реальних людей**. Місток:

| Етап | Хто бачить продукт | Навіщо |
| --- | --- | --- |
| Внутрішній MVP | команда | файл збирається, credits, Brand Kit |
| **Закрита бета** | **5–10 запрошених** власників малого бізнесу (салон / кав’ярня / фітнес), інвайт, Free або ручні credits, **без реклами і без публічного «запуску»** | 20–50 реальних mp4 → `actual_cost_gbp`; якісні інтерв’ю; чорновий retention (на n=10 **не** приймати go/no-go по постах) |
| Публічний лендінг | будь-хто | після стабільного файлу, логів бети **і** §10.1 (privacy / content policy) |
| Платний CAC-тест | реклама | перевірка гіпотези §9.5, не змішувати з бетою |

Публічний ads-запуск до закритої бети — заборонений цим ТЗ.

## 2. Scope

### 2.1 Розведення: код зараз vs прийнятий MVP

| Блок | У коді зараз | Обов’язково для прийняття MVP |
| --- | --- | --- |
| Лендінг, auth, JWT, 400 free credits | так | так |
| Create: Short video / Image Post + промпт | так | так |
| 6 кроків студії, credits, Brand Kit, Library | так | так |
| `ai_generations` (собівартість) | так (API) | так у логах. UI на Credits **схований** |
| Idea / Script / Visuals / Captions | так. Visuals **потребують** `OPENAI_API_KEY` (інакше 503 «We can’t make pictures right now…», причина в логу). Captions = scene-level | так; word-level не вимагається в MVP |
| Voice | TTS → `voice.mp3` (`audio_url`); JSON = direction | так; без файлу крок не done |
| Create | ffmpeg → `reel.mp4` 1080×1920, плеєр + Download | так |
| Регенерація кроку / одного кадру | `regenerate` + `sceneId` (8 cr) | так — §7.2–7.3 |
| Керування акаунтом | сторінка `/app/account`: профіль, пароль, експорт даних, вихід усюди, видалення (`DELETE /auth/account` з паролем) | так для етапу 4; на беті вже є |
| Вертикаль Brand Kit | `salon` / `cafe` / `fitness` | так |
| S3, постійний Download URL, HQ | немає | **не MVP** |
| Закрита бета / публічний лендінг | код є; зовні не запускали | бета §1.5 перед ads |
| `poster.ts` / compose | файл є, **не** в пайплайні | не підключати; картинка = відповідь OpenAI |
| Поля флаєра в Studio | код без UI | не потрібні: текст уже на JPG |

**Критичне правило:** не показувати продукт *публічно* з обіцянкою «готовий Reel», доки немає файлу. TTS (OpenAI `tts-1`) + ffmpeg — **зафіксовані** (§1.4), не «фаза 2» і не відкритий вибір. Зовнішні *платні* користувачі — після закритої бети (§1.5).

Що лишається *після* прийняття MVP (коли файл уже є):

- завантаження в AWS S3;
- кнопка Download з постійним URL;
- вища якість / стабілізація / музика;
- Stripe webhook, коли з’явиться публічний checkout (зараз без ключа — **403**, не studio-grant).

### 2.2 Свідомо не робимо в v1

- власний відеоредактор рівня CapCut;
- 100 AI-моделей на вибір користувача;
- мобільний + web + desktop одночасно (тільки web; web адаптивний під телефон — §4.2, нативних застосунків немає);
- складна система шаблонів / маркетплейс (окрім 3 нішевих каркасів у §1.3);
- шедулер у соцмережі;
- власна AI-модель;
- blockchain / crypto / токен;
- Canva-подібний canvas, шари, drag-and-drop;
- командні акаунти, ролі, SSO;
- batch / кілька варіантів на один промпт (агентство);
- клонування «мого голосу» креатора.

### 2.3 Формати на Create — що є і що буде

На екрані Create п’ять карток. Власник обирає **намір** (що хоче отримати). Модель, голос і вендора він **не** обирає.

**Працюють зараз дві.** Три інші показують «скоро» і проєкт не створюють.

> This format is next. Start with a short video or still images.

TikTok окремою карткою немає: той самий файл, що й Коротке відео. Старі проєкти `tiktok` = той самий пайплайн.

#### Що спільне для всіх кнопок

Один стек. Кнопки відрізняються лише тривалістю, розміром кадру і текстом сценарію.

| Навіщо | Зараз у коді | Потім, після бети |
| --- | --- | --- |
| Текст, ідея, сценарій | OpenAI `gpt-4o-mini` | те саме |
| Картинка | OpenAI `gpt-image-2.5-sunburst` | те саме |
| Голос | OpenAI `tts-1` (голос `nova`) | те саме |
| Збірка ролика | ffmpeg | те саме |
| Рух у кадрі | **немає** — картинка стоїть | **Kling**: бере вже готову картинку сцени і робить з неї короткий кліп 5–8 с. Потім ffmpeg склеює кліпи + наш голос |

Зараз у коді **немає** Kling, Runway, Veo, Seedance і ElevenLabs як голосу.

**Як з’явиться рух.** Не нова кнопка «Animate». Власник як і зараз тисне Коротке відео (або пізніше Рекламу / Відео). Після картинок система сама віддає кадр у Kling. Імена моделей на екрані не показуємо.

Kling також уміє зробити відео одразу з тексту, без картинки. **Цього не беремо першим:** тоді зникне крок з кадрами, Brand Kit на фото не втримається, сцени роз’їдуться. Свій звук Kling вимикаємо — голос у нас уже є. Довгий ролик Kling одним шматком не робить (зараз до ~15 с за виклик), тому 30 с чи 90 с = кілька сцен, склеєних у нас.

#### Чотири кнопки простими словами

**1. Коротке відео** (`instagram_reel`) — **вже працює**, 150 credits.

Для стрічки Instagram / TikTok. Власник пише речення на кшталт «30 секунд про атмосферу салону». На виході вертикальний ролик ~30 с (`reel.mp4`, 1080×1920): 4–6 картинок + голос + субтитри.

Після бети, якщо «просто картинки» мало хто хоче викладати — ті самі картинки оживить Kling. Кнопка не змінюється.

**2. Картинка / пост** (`image_post`) — **вже працює**, 13 credits.

Без голосу і без відео. Один JPG **цілком з OpenAI** (фото, запрошення, інфо, офер). Ми нічого не накладаємо. Kling не потрібен.

**3. Реклама** (`advertisement`) — **заглушка**. Окрема кнопка, не зливається з Коротким відео.

Для платного просування: «хочу клієнтів». У брифі мають бути офер або товар і для кого. Без цього система просить уточнити, не вигадує знижку. На виході короткий рекламний ролик 15–30 с (`ad.mp4`), частіше 9:16 або 1:1.

Технологія та сама: GPT → картинка OpenAI → `tts-1` → ffmpeg. Рух — той самий Kling, коли він уже живий на Короткому відео. Seedance — лише пізніше, якщо треба товар з кількох референс-фото. Credits перерахувати **до** відкриття кнопки.

**4. Відео** (`video`) — **заглушка**. Окрема кнопка, не «увімкнути рух» і не заміна Короткого відео.

Для ролика не в Reel: сайт, YouTube, екран у залі. Історія «як у нас фарбують / варять каву», без жорсткого оферу. На виході 45–90 с, часто 16:9 (`video.mp4`, 1920×1080).

Технологія та сама, лише більше сцен (8–12) і ширший кадр. Не Kling «з промпту на всю хвилину»: він не робить 90 с за раз, і ми втратимо свої картинки. Credits перерахувати **до** відкриття: сцен і картинок більше.

**5. Пост у соцмережі** (`social_post`) — теж заглушка. Поки не розписуємо: картинку вже закриває кнопка 2.

#### Що не плутати

- **Відео** ≠ рух. Рух буде всередині вже обраного формату, спочатку в Короткому відео.
- **Реклама** ≠ Коротке відео зі словом «знижка». Інший сценарій (офер → заклик записатися) і інший файл.
- Дві заглушки **не зводити** в одну картку. Інакше незрозуміло, що тиснути, і не зійдуться credits.
- Не віддавати фініш у CapCut / Canva.

#### Коли відкривати заглушки

1. Закрита бета: лише Коротке відео (сторіборд) і Картинка.
2. Якщо після 20–50 роликів картинок мало — Kling на **Коротке відео** (§12.1). Спочатку перерахувати credits: рух дорожчий за кадр.
3. Гейт §11.11 (щонайменше 40 людей з першим готовим mp4).
4. Відкрити **Рекламу**.
5. Потім відкрити **Відео**.

`image_post` уже відкритий як виняток (явний запит: не лише відео).

## 3. Користувацькі сценарії

### 3.1 Щасливий шлях (Reel)

1. Користувач відкриває лендінг, тисне **Start creating**.
2. Реєструється (ім’я, email, пароль ≥ 6 символів) → отримує **400 credits**, план Free, порожній Brand Kit.
3. Бачить «What do you want to create?», обирає **Коротке відео**.
4. Пише, що хоче створити. **Одне речення зазвичай вистачає**; якщо ні — короткий абзац (офер, адреса, для кого), до 2 000 символів. Не бриф на сторінку і не обов’язок «рівно одне речення».  
   Приклад: `Create a 30-second Reel about the best places to visit in London.`  
   Або довше: `Reel for my salon in Shoreditch. Tuesday walk-ins 20% off. Warm, not salesy. Show the chair, not stock hair.`
5. Відкривається студія. Кроки (кнопка на кожен):
   1. **Idea** (5 cr) — концепція, хук, візуальний напрям;
   2. **Script** (10 cr) — 30 с, 4–6 сцен, текст voiceover;
   3. **Visuals** (40 cr) — кадр на кожну сцену (9:16);
   4. **Voice** (30 cr) — спочатку JSON-інструкція голосу, потім **TTS → аудіо** (див. §6.8);
   5. **Captions** (10 cr) — таймкоди субтитрів;
   6. **Create** (55 cr) — **збірка mp4** + статус `ready`.
6. Разом **150 credits**. Баланс: 400 → 250.
7. Користувач має mp4 на диску, плеєр і Download у студії. Проєкт у Library.
8. Якщо голос або кадр не сподобався — користувач **вибирає**: лишити це (Make повторно = 0 credits, без AI) або **Regenerate** за credits кроку (§7.2). Перші два повтори — звичайна ціна. Далі все ще можна, але **2× credits** і confirm. Не обов’язково новий проєкт.

### 3.2 Brand Kit

Користувач один раз задає бренд. Далі промпт «Create a Reel promoting my coffee shop» вже має кольори, шрифт, тон, Instagram, і якщо є — **лого та 2–3 фото** (зал / людина / товар). Після кількох готових роликів Kit має **підхоплювати патерни** з історії (не лише форму) — див. §1.3.

### 3.3 Недостатньо credits

Якщо на кроці не вистачає балансу — 402, текст *Not enough credits. Buy a pack or upgrade your plan.* і посилання на `/app/billing`.

### 3.4 Покупка

- підписка Creator / Pro / Business нараховує місячний пакет (**залучення**);
- Buy credits — разові пакети (**маржа**) — стратегія в §9.4;
- без `STRIPE_SECRET_KEY` checkout **закритий**: кнопки Choose / Buy сховані, `POST /billing/checkout` → **403**. Credits на беті — Free 400 або вручну. Studio-grant (нарахувати план без Stripe) **прибрано**.

### 3.5 Щасливий шлях (Image / Post)

1. На Create обирає **Image / Post** — **один** формат, не окремі продукти «фото / запрошення / інфо».
2. Опційно обирає **what kind of post** (`image_intent`):
   - **Just a photo** — настрій, місце, хто на кадрі;
   - **Invitation** — що за івент, коли, де;
   - **Information** — факт (години, зміна, нагадування);
   - **Offer** — офер, коли діє, для кого.
   Чип **не** новий `type`. Промпт картинок завжди з повного брифу — не шаблон «одна атмосфера».
3. Пише бриф. Можна довгий: що показати, яка інформація, програма. Приклади: photo `A quiet morning table at my café.`; invite повний текст івенту з годинами; info `Closed Monday 6 May.`; offer `Tuesday walk-in offer.`
4. Студія — **2 кроки** (13 credits разом). `script` / `voice` / `captions` / `render` — 400.
   1. **Idea** (5 cr). Концепція + **кадр** (`shot`). Для **invite** ще `invite_json` (факти з брифу; на картинку не йде).
   2. **Перевірка кадру** (0 cr, **без AI**). Картка «Знімемо ось це»: одне речення-підсумок і поля *у кадрі / де / камера / люди / світло й настрій / слова на картинці*. Кнопки **«Так, знімай це · 8 кр»** (підтверджує й одразу запускає Pictures) і **«Змінити кадр · безкоштовно»**: відкриває всі поля для редагування, **«Зберегти кадр»** пише їх у `idea_json.shot` дослівно — жодного запиту в AI, жодних кредитів, без ліміту. AI отримує вже виправлений кадр лише в кроці Pictures. «Слова» порожньо = фото без напису; «одним реченням» порожньо = збирається з «у кадрі» + «де».

**Слова на фото — лише на прохання.** Для kind `photo` одразу після Ідеї `keepWordsHonest`: якщо в «словах» щось є, а бриф явно не просить напис (лапки, «напис / підпис», `caption`; заперечення «без напису», «не слова» не рахуються) — текст переїжджає в «у кадрі», «слова» порожні. Флаєри (invite / info / offer) не чіпаються. Що власник сам написав у «словах» при редагуванні — лишається. Ідея не губить деталей брифу (квіти, стілець, світло — у «в кадрі»), «пара» біля кави = пар, не люди. Мета — щоб власник побачив і поправив, що знімуть, **до** оплати картинки, і не перезнімав одне й те саме.
   3. **Pictures** (**8 cr**) — один запит в OpenAI, один готовий JPG. Модель малює **всю** сторінку: фото і, якщо треба, слова. Ми **не** складаємо шар. Промпт починається з підтвердженого кадру, бриф іде як факти. Можна перезняти цей кадр.
5. Download — **назва файлу каже, що це**: тип (фото / інформація / запрошення / пропозиція / рілс), тема (назва запрошення або заголовок ідеї, до 40 символів, літери будь-якої абетки), мова написів (укр / англ; для фото без слів — не пишемо) і формат (квадрат-1x1, портрет-4x5, сторіз-9x16, широка-1.91x1, висока-2x3), слова мовою інтерфейсу; напр. `запрошення_безкоштовні-заняття-з-йоги-арт-терапії_укр_сторіз-9x16.jpg`, `рілс_осінній-розпродаж_укр_сторіз-9x16.mp4` (`frontend/src/lib/fileName.ts`). *Would you publish?* і *Share* **сховані**.
6. Без voice і mp4.

### 3.6 Картинки — як є

Для **photo, invite, info, offer** одне й те саме: Pictures віддає **повний знімок з OpenAI**. Окремого фону і нашого тексту немає і **не плануємо** в цьому документі.

| Kind | Idea | Pictures | Файл |
| --- | --- | --- | --- |
| **photo** | концепція | OpenAI, **1:1** | `still-1.jpg` = відповідь моделі |
| **invite** | концепція + `invite_json` (лише в БД) | OpenAI **1024×1536**: флаєр цілком, літери в пікселях | той самий JPG |
| **info / offer** | концепція, без `invite_json` | те саме: факт / офер малює модель | той самий JPG |

Власник пише бриф, тисне Idea → Pictures, завантажує JPG. Полів «дата / адреса» на екрані немає. `PATCH /invite` пише JSON і **не** перемальовує файл.

`poster.ts` (`composeInvitePoster` тощо) у репо є, пайплайн його **не** кличе. Не підключати для тексту постера. **Виняток лише для лого:** якщо `logo_on_photos=1`, після живого кадру **ffmpeg** накладає PNG/JPG власника в кут. Це не compose постера і не «намалюй лого» в OpenAI. **Другий виняток — рядок контактів:** якщо `contact_on_photos=1` і є Instagram або сайт, на **фото-пости** (`kind=still`, не флаєри, не Reel, не remake) ми малюємо маленьку темну «пігулку» `@name · site` унизу ліворуч (`@resvg/resvg-js` → PNG, ffmpeg `overlay`). Текст друкуємо **самі**, модель його не малює — без помилок у написанні.

Кадри **Короткого відео** — інше: промпт просить фото без літер; слова — голос і SRT.

### 4.1 Вимоги до екранів

**Landing.** Заголовок-обіцянка, CTA «Create a Reel». Поки немає mp4 — не показувати як готовий продукт. Коли файл є: **закрита бета за інвайтом**, публічний лендінг — окремий етап (§1.5). Copy не зменшувати до «сторіборда». Перемикач **EN / УК** на лендінгу, auth і в сайдбарі; вибір у `localStorage` (`auteur.lang`). Бриф і відповідь AI лишаються мовою запиту.

**Database (внутрішній).** Лише читання, живі дані: вибір таблиці, найновіші рядки першими, сторінки по 50, довгі значення обрізаються. Доступ: email з env `ADMIN_EMAILS` (звіряється з email акаунта в базі) і/або id з `ADMIN_USER_IDS` (суворіше; свій id видно на `/app/account?id`); порожньо = вимкнено. Адреса з `ADMIN_EMAILS` дає доступ лише після підтвердження пошти, тож чужу адресу зайняти не вийде. Для всіх інших API відповідає 404. Ніколи не віддає `password_hash`, `preview_token`, `token_version`, `verify_token_hash`. Назва таблиці береться лише зі списку реальних таблиць. Не перекладається (службовий екран).

**Іконка вкладки.** Serif «A» кольору кремового паперу (`#f4efe8`) з мідною (`#e8a87c`) перекладиною на темному фоні бренду, тонка мідна рамка (`#c45c26`). Файли: `frontend/public/favicon.svg` (основна), `favicon-32.png`, `favicon.ico`, `apple-touch-icon.png` (180, без прозорості), `icon-192/512.png`. `theme-color` = `#0c0b0a`.

**ComfyUI (необов’язково, лише локально).** Якщо задано `COMFYUI_URL`, фото та кадри Reels (kind `still`/`video`) малює локальний ComfyUI через його HTTP API (`/prompt`, `/history`, `/view`) за workflow у API-форматі (`backend/comfy/workflow.json`, інакше `workflow.example.json`) із плейсхолдерами `{{prompt}} {{negative}} {{checkpoint}} {{width}} {{height}} {{seed}} {{steps}} {{cfg}}`. Дизайнерські флаєри зі словами, картинки з прикладами/фото бренду та редагування існуючої картинки лишаються на OpenAI. Правило: `COMFYUI_URL` задано → малює ComfyUI; не задано → OpenAI. Якщо ComfyUI вимкнений, помилився або не вклався в 300 с (завдання скасовується), власник бачить «зараз не вдається зробити картинку» (без слова ComfyUI), причина — в логу; застосунок **не** йде до OpenAI (немає прихованих витрат); `COMFYUI_FALLBACK=openai` вмикає перехід на OpenAI. Кредити однакові. На хостингу змінна не задається, тож продакшн завжди на OpenAI. Не відкривати ComfyUI в інтернет: він без авторизації.

**Прев’ю картинки.** У Studio для image_post (photo, invite, info, offer) поверх картинки нічого не накладається: службовий підпис сцени «Finished picture» більше не показується. Підписи на прев’ю лише для Reels.

**Тексти помилок (для власника, не для розробника).** Користувач ніколи не бачить назв сервісів і налаштувань: ComfyUI, OpenAI, ключ API, `.env`, `COMFYUI_*`, ffmpeg, назви моделей, верифікація організації, «Unknown step/scene». Усі тексти, які бекенд може показати через збій, зібрано в `backend/src/services/userErrors.ts` (`USER_ERRORS`), кожен має український рядок у `frontend/src/i18n/errors.ts`. Технічна причина — лише в логу сервера (`Image frame failed …`, `ComfyUI failed: …`, `Step <step> (<id>) failed …`, `<METHOD> <path> failed …`).
- Помилка з 4xx-статусом (кинута навмисно, напр. «Not enough credits…», «Check the shot first…») показується як є.
- Будь-яка інша (5xx, без статусу, падіння провайдера чи ffmpeg) проходить через `forOwner` / `publicError`: пишемо в лог, власнику — простий текст кроку: картинка «We couldn’t make the picture. Try again — if it happens again, describe it a little differently.», кадри Reel, голос, субтитри, відео, текст ідеї/сценарію; поза кроками — «Something went wrong. Try again in a minute.».
- Картинки: ключ / білінг / модель недоступна / організація не верифікована / ComfyUI не відповідає / немає `OPENAI_API_KEY` → «We can’t make pictures right now. Try again in a few minutes.» (503 для відсутнього ключа); фільтр безпеки → «We can’t make a picture from this description. Try saying it a little differently.»; 429 → «Lots of requests right now. Try again in a minute.».
- Неможливі з UI запити (невідомий крок, формат, сцена, версія) → «Something went wrong. Refresh the page and try again.».
- Фронт: немає з’єднання → «We can’t reach the studio. Check your internet and try again.»; відповідь без тексту → «Something went wrong. Try again in a minute.».
- Те саме для підказок в інтерфейсі: без назв постачальників і налаштувань («З усього брифу робимо одну готову картинку», а не «бриф іде в OpenAI»; «Кредити нараховано» без згадки ключів Stripe; план Free — «На час бети ціни фіксовані», без TTS). Службовий журнал вартості AI (провайдер, модель, £) прихований прапорцем `SHOW_AI_COST_LOG = false`.

**Auth.** Ім’я (тільки signup), email, пароль. Помилки зрозумілою мовою.

**Підтвердження пошти.** Без нього одна людина могла б робити багато акаунтів і щоразу брати 400 кредитів (до £2 собівартості кожен, див. `docs/COSTS.md`).
- **Вмикається лише коли пошта справді доходить** (`EMAIL_VERIFICATION`, дефолт `auto`): є `RESEND_API_KEY` **і** `MAIL_FROM` не на `@resend.dev` (тестовий відправник Resend доставляє лише власнику акаунта Resend). Інакше — як раніше: 400 кредитів одразу, без листа й банера, генерація не блокується. `on` — завжди (без ключа посилання в лозі API, для локальних тестів); `off` — ніколи. Тож без власного домену в Resend прод (Railway) працює як до цієї зміни.
- Акаунти, створені поки перевірка вимкнена, отримують кредити одразу, але **не** вважаються підтвердженими: коли перевірку ввімкнуть, вони побачать банер і підтвердять пошту одним кліком (кредити вдруге не нараховуються).
- Signup створює акаунт з **0 кредитів** і надсилає лист із посиланням `APP_URL/verify-email?token=…` (мова листа — з `Accept-Language`). У базі зберігається лише sha256 токена (`users.verify_token_hash`), посилання діє **48 год**, новий лист замінює старий.
- До підтвердження можна увійти, дивитися, писати бриф і створювати проєкт, але **будь-який крок генерації → 403 `email_unverified`** «Confirm your email first — we sent you a link…». AI не викликається, кредити не чіпаються.
- `POST /auth/verify-email { token }` (без входу, бо лист можуть відкрити на іншому пристрої) ставить `email_verified_at` і **один раз** нараховує 400 (`credit_transactions` grant «Free plan credits»; повторне підтвердження після зміни пошти не дає кредитів удруге).
- У застосунку, поки пошта не підтверджена, зверху банер «Підтвердіть пошту, щоб отримати 400 безкоштовних кредитів…» з кнопкою **Надіслати ще раз** (`POST /auth/verify-email/resend`; не частіше 1 разу на хвилину і 5 на годину).
- Зміна пошти в Account знімає підтвердження й надсилає нове посилання.
- Signup: не більше 5 на годину з однієї IP (`trust proxy` = 1 для Railway).
- Листи — через **Resend** (`RESEND_API_KEY`, `MAIL_FROM` з доменом, підтвердженим у Resend). Без ключа лист не відправляється, посилання пишеться в лог API (локальна розробка). Помилка відправки не ламає реєстрацію: її видно в лозі, власник натискає «Надіслати ще раз».
- Акаунти, створені до цієї зміни, вважаються підтвердженими (міграція один раз ставить `email_verified_at`).
- `ADMIN_EMAILS` працює лише для **підтвердженої** пошти. Кожне поле пароля (Auth і Account) має кнопку «око» — показати / сховати введене (`PasswordInput`).

**Create.** Сітка 5 форматів — **§2.3**. **Коротке відео** / Картинка — активні. **Відео** і **Реклама** — окремі заглушки, не одна кнопка. Social — теж «soon». TikTok окремим чіпом **не** показуємо. Промпт — від 8 до 2 000 символів. Copy: речення може вистачити; якщо ні — офер, місце, для кого. Reel 150 cr · Image / Post 13 cr. Перемикач **Use brand kit / Ignore** (`use_brand`, дефолт так): з брендом у **текст** промпта йдуть назва, кольори, шрифт, тон, ніша; зал / людина / товар — ще файли в `images.edit` (лише для фото-постів і Reel, **не** для оформлених флаєрів invite / info / offer); лого на кадр — лише якщо `logo_on_photos` (наш шар, не малюнок моделі). Без бренду — лише бриф. UI показує, що піде на картинку. **Це єдине місце вибору «з брендом / без»**: у Studio він лише читається. Для **invite / info / offer** — чіпи **Follow the brief / English / Ukrainian** (`picture_language`: порожньо / `en` / `uk`). Якщо бриф іншою мовою — **спочатку перекласти бриф**, потім намалювати той переклад. Усе на вибрану мову, включно з іменами, датами й адресами. Photo і Reel — без цього чіпа.

**Компонування Create (щоб не було «забагато»).** Зверху форма, для Image Post — два компактні рядки чіпів: *Який це пост?* (Просто фото / Запрошення / Інформація / Офер) і *Де ви опублікуєте?* (Пост: квадрат / Пост: портрет / Stories і Reels / Facebook: широкий), кожен з одним рядком підказки для вибраного пункту. Одразу під ними — поле брифу й кнопка. Усе другорядне зібране в згортці **«Додаткові налаштування»**. Вона виглядає як кнопка (рамка, шеврон ▾, підказка «Натисніть, щоб змінити: бренд-кіт, приклади картинок, збережені брифи»), а поточний вибір показаний чіпами («Так, з брендом», «Як у брифі», «Приклади: 2»), щоб не плутати її зі звичайним текстом: бренд-кіт, мова слів на флаєрі, приклади картинок, збережені брифи. Нічого не прибрано, лише згорнуто.

**Studio.** Коротке відео: вертикальний прев’ю 9:16 (після Create — `<video>` з mp4), 6 кроків. Image Post: прев’ю має пропорцію **вибраного формату** (1:1 / 4:5 / 9:16 / 1.91:1; старі проєкти — photo 1:1, флаєр 2:3), `contain` для флаєрів. На екрані JPG з OpenAI цілком. Полів флаєра немає; `PATCH …/invite` лише JSON. Зверху лише **Бриф** (textarea), `Save brief` (PATCH, 0 cr) і `Copy brief` (з fallback, якщо браузер блокує clipboard). Рядок `image post · …` і нагадування «кіт N% — додайте лого» **не показуємо** (лого опційне). На Create — список збережених брифів, клік вставляє. Після Pictures: Download JPG; takes поруч; *Share* і *Would you publish?* **сховані** (`SHOW_SHARE_AND_PUBLISH`). На **invite / info / offer** після JPG: **Same picture in English / Ukrainian** · **8 cr** — бере **картинку на екрані** (поточний take, не обов’язково live `still-1.jpg`) і **бриф**, шле в `images.edit`. Спочатку **gpt-4o-mini зчитує слова, які вже написані на вибраному take** (vision OCR) і перекладає їх **рядок у рядок** обраною мовою: бриф власника — глосарій, імена, дати й адреси теж, жоден рядок не губиться (DJ, дата, адреса, ціна, бейдж, charity box); fallback — переклад усього брифу. Далі `images.edit` («Translate the text in this image to …», змінюються лише літери, сцена та композиція лишаються)  **повертає картинку, яка зараз на екрані** (вибраний take, не останній live-файл, якщо клікнули інший варіант) тією мовою (основна модель `OPENAI_IMAGE_MODEL` + `input_fidelity=high`, якщо модель його приймає; без generate). Нової сцени немає. Попередній take лишається, restore безкоштовний. Лого **не** штампуємо вдруге. Photo і Reel — без цієї кнопки. Після JPG також поле **змінити слова** (додати / прибрати рядок) · **8 cr** — `images.edit` картинки на екрані, `copyEdit`. Photo теж. **Клік по картці take** (не лише по кнопці) робить його вибраним: саме він іде в Same picture, зміну слів і Download (скачується те, що на екрані). Рядка про «мову слів на картинці» **немає** — ми не знаємо реальну мову take. Вибір «з брендом / без» у Studio **лише для читання** (що бренд використовує); змінити можна на Create. Панель **одного** поточного кроку + `Make {step} · N credits`. Якщо крок уже є — `Not this {step}? Try again · N credits` (idea/script — confirm каскаду). Після 3 спроб: `Keep this, or another try · 2×`. Кадри з `placeholder: true` видимі. **Файл варто завантажити зараз**; проміжні відео-артефакти можуть зникнути через 7 днів, `reel.mp4` і `still-*.jpg` тримаємо 90 днів.

**Brand Kit.** Одна форма з чотирма секціями-картками та навігацією-чипсами зверху (Бізнес · Вигляд · Лого й фото · Контакти): (1) **Бізнес** — назва, чим займаєтесь (salon / café / fitness / **other** + вільний текст), адреса; (2) **Вигляд** — кольори «Акцент» і «Фон» (з попередженням, якщо контраст < 3:1), тон-чипси з прикладом фрази + optional note, шрифт заголовків (список або **свій шрифт**, див. нижче); (3) **Лого й фото** — плитки лого + зал / людина / товар (замінити / прибрати); (4) **Контакти** — Instagram, сайт і блок «Де це з’являється на картинках» з двома перемикачами (лого в куті фото; @нік і сайт на фото-постах), які неактивні й пояснюють чому, поки немає лого чи контактів. Усе опційне, **не** блокер Create. Праворуч (на мобільному — зверху) липка **жива прев’ю-картка** з назвою, шрифтом, тоном, лого й контактним рядком (CSS, 0 AI; не картинка від AI) і **чеклист** із 5 пунктів, кожен веде до свого поля. Внизу липка панель збереження: «Є зміни…», «Скасувати зміни» (перечитує з сервера), «Зберегти зміни». Learned-картка — у згортці «Чого навчився Auteur» внизу. Індикатор «Brand kit N% complete — …» рахує **лише те, що змінює картинки й голос**: кольори (відмінні від дефолту), тон (один зі справжніх чипів), назва, чим займаєтесь, лого — 5 пунктів, `ready` від 50%. Сайт, Instagram і фото в % **не** входять — не нагадувати. **Навіщо Instagram і сайт:** (1) у сценарії Reel остання сцена закликає знайти їх — у `voiceover` вимовно («find us on Instagram, mysalon», без @ і https), у `cta` та останньому `onScreen` — точний текст `@name` / `site`; нічого вигадувати; (2) опційно рядок на фото-постах (перемикач «@нік і сайт на фото-постах», `contact_on_photos`, дефолт ні; показується, лише коли заповнене одне з полів; на флаєрах — ні, там власник пише це в брифі). **Адреса бізнесу** (`address`, до 160 символів, одне поле): друкується на флаєрах **invite / offer / info** лише коли бриф **не називає місця**; якщо бриф має своє місце — береться воно; на фото — ніколи; текст береться дослівно з Kit, нічого не вигадується; вимкнено разом із брендом (`use_brand=0`). Також іде в текст Idea як «Business address». Власник не повторює адресу в кожному брифі. Зі сторінок нічого не читаємо. `@name` нормалізується (URL → нік), сайт без протоколу та `www`. Тон розпізнається за початком речення (старі тексти не губляться). HEX у полі перевіряється: некоректний колір підсвічується, Save зупиняється з поясненням (не мовчки дефолт). **Reset learning** — у згортці Learned. Лого: `POST /brand/logo` — **max 2 MB, лише PNG/JPEG**, SVG заборонено; `DELETE /brand/logo` стирає лише лого, не фото. `GET /brand/logo` — файл, `nosniff`. Фото: `POST/DELETE/GET /brand/ref/{place|people|product}` — той самий ліміт. **Свій шрифт:** `POST /brand/font` (`{ font: data-url }`, **TTF або OTF до 2 MB**, перевірка за байтами й таблицею `name`), `GET` / `DELETE /brand/font`; файл у `data/media/brand/{userId}/font.ttf|otf`. Після завантаження `brand_kits.font` = справжня назва сімейства з файлу (Save її не перезаписує), після видалення — `Fraunces`. Де працює: (1) прев’ю Brand Kit — справжніми літерами (`FontFace`); (2) **назва бізнесу на фото — точно цим шрифтом**: якщо лого немає, а перемикач «Лого в куті фото» увімкнено (тоді він зветься «Назва бізнесу в куті фото»), ми самі друкуємо назву на плашці кольору «Фон» шрифтом власника (resvg → ffmpeg), модель її не малює; (3) **написи на флаєрах** (`kind=poster`) — у `images.edit` іде зразок шрифту (`font-sample.png`: назва, латиниця, кирилиця, цифри) з інструкцією писати всі слова цим шрифтом; модель повторює стиль, але **не буква в букву**; ≈ +$0.005–0.01 за флаєр. Фото-пости без слів і переклад готової картинки зразок не отримують. У mp4 шрифт не вшивається. **Вбудовані Nunito і Montserrat** (Regular, ліцензія OFL, файли й ліцензії в `frontend/public/fonts`, роздаються як `/fonts/*.ttf`): якщо їх обрано у списку і свого файлу немає, вони працюють так само, як завантажений шрифт — прев’ю, назва бізнесу на фото, зразок для флаєрів. Решта шрифтів зі списку — лише підказка моделі. Якщо `use_brand=1` — у **текст** Idea/Script/Pictures йдуть назва, кольори, ніша, лого (як знак, не «намалюй його») і опис фото. У **`images.edit`** йдуть лише зал / людина / товар — **не лого** і **не на оформлених флаєрах** (`kind=poster`: invite / info / offer — фото не шлемо взагалі). Для фото-постів і Reel промпт каже: брати фото лише якщо сцена про їхній зал / людину / товар, інакше ігнорувати (флаєр на дискотеку не стає кав’ярнею). Fallback — `images.generate`. Перемикач **«Лого в куті фото»** (`logo_on_photos`, дефолт ні): власник не пише це в брифі. «Поставити» = **наш шар файлу** після кадру (ffmpeg), не малюнок моделі. **Кут** обирає власник (`logo_position`: `top-left` / `top-right` / `bottom-left` / `bottom-right`, дефолт `bottom-right`; інше значення → дефолт); вибір видно, коли перемикач увімкнено, прев’ю показує той самий кут. Модель отримує вказівку не малювати слова в цьому куті. Рядок «@нік · сайт» стоїть унизу ліворуч; якщо лого теж унизу ліворуч — рядок переїжджає вниз праворуч. **Лого на вже готову картинку:** блок показується, лише коли лого не ставиться автоматично — проєкт без бренду (`use_brand=0`) або в Kit вимкнено «Лого в куті фото»; якщо бренд увімкнено й лого автоматичне (AI готує для нього місце), блок схований, щоб не плутати. У Studio під готовою картинкою — «Додати логотип» з вибором кута (дефолт з Kit), безкоштовно, картинка не перемальовується; результат — нова версія, стару без лого можна повернути. Якщо наше лого вже стоїть (автоматично чи кнопкою) — кнопки «Перенести логотип сюди» і «Прибрати логотип». Щоразу, коли ми ставимо лого, зберігаємо чисту копію тієї ж картинки без нього (уже з рядком «@нік · сайт») і ключ у `visuals[].clean`; так лого переноситься без дублювання і прибирається без AI. Повторне збереження кадрів не ставить лого вдруге на кадр, де воно вже є. Кнопки лого працюють з картинкою, **вибраною в порівнянні версій** (`versionId`): вона спершу стає поточною, потім змінюється; «Прибрати логотип» показується лише коли на вибраній картинці наше лого (`ourLogo`) і завжди безкоштовна: **усі** наші лого (і накладені одне на одне) прибираються безкоштовно — повертаємо картинку такою, як її віддала модель: найближча попередня версія з `generation_id` (версії «лого додано / прибрано» генерації не мають), а якщо на ній було наше автоматичне лого — її чиста копія. «Додати / Перенести» теж завжди ставить лого на цю картинку моделі, тож лого не накопичуються. Сервер рахує для кожної версії `ourLogo` (є `clean` або версія без генерації відрізняється від картинки моделі). Платного AI-прибирання немає, щоб не плутати: лого, вшите в старі картинки до появи чистих копій, прибирається лише новою картинкою. **Гармонійне місце для лого:** коли лого ставиться автоматично (перемикач у Kit), у промпт картинки (`brandLook`, і фото, і флаєри) додається рядок: у якому куті буде лого, його форма (wide / tall / square) і до 3 головних кольорів, прочитаних із самого файлу (`logoLook.ts`, кеш `logo-look.json` поруч із лого; схожі відтінки зливаються в один). Модель просимо залишити в цьому куті спокійне місце ≈ 1/6 ширини без слів, облич і дрібної текстури, з фоном, на якому такий лого добре читається, і м’яко повторити його кольори в картинці; лого чи знак не малювати, назву бізнесу в цей кут не ставити. Без лого, але зі шрифтом — те саме для назви бізнесу кольором бренду. Файл лого моделі не передається. **Reel без голосу:** голос необов’язковий. На кроці «Голос» поруч із «Записати голос · 30 кредитів» — «Без голосу» (`POST /projects/:id/voice-off {off}`, поле `projects.voice_off`): безкоштовно, крок вважається пройденим (у рядку кроків «Голос · без голосу»). Субтитри без голосу — написи сцен зі сценарію (`onScreen`), кожен на свою частку тривалості; без AI, **0 кредитів**. Відео: кадри + субтитри + тиха аудіодоріжка (`anullsrc`, щоб Instagram і телефони грали як звичайне відео), тривалість зі сценарію; рендер коштує як завжди. «Додати голос» (або запуск кроку «Голос») вмикає голос назад; при будь-якому перемиканні субтитри й відео стираються й робляться знову (з підтвердженням). Рендер без голосу й без «Без голосу» — 400 «Record the voice first, or choose No voice.» **Reel без субтитрів:** так само, як голос: на кроці «Субтитри» — «Без субтитрів» (`POST /projects/:id/captions-off {off}`, поле `projects.captions_off`), безкоштовно, крок пройдено («Субтитри · без субтитрів»); відео збирається без написів унизу. «Додати субтитри» або запуск кроку «Субтитри» вмикає їх назад; відео після перемикання збирається знову. Рендер без субтитрів і без «Без субтитрів» — 400 «Make the captions first, or choose No captions.» Можна поєднувати з «Без голосу» — тоді відео лише з кадрів і тихої доріжки. **Ручні правки Reel (безкоштовно, без AI):** у перегляді кроку «Сценарій» — «Редагувати сценарій»: заклик у кінці, напис на екрані й текст для голосу кожної сцени (`PATCH /projects/:id/script`, нова версія сценарію). Кадри лишаються; субтитри й відео стираються; якщо змінився текст для голосу — голос теж (з попередженням про 30 кредитів). У перегляді кроку «Субтитри» — «Редагувати субтитри»: текст, початок і кінець кожного рядка в секундах, додати / прибрати рядок (`PATCH /projects/:id/captions`, до 60 рядків, рядок без тексту чи з кінцем ≤ початку відкидається, порожній список → 400); відео після цього збирається знову. **Лого на кадрах Reel:** кадр 2:3, а mp4 9:16 — бокові смуги обрізаються, тож лого ставиться всередині видимої частини (зсув на обрізану смугу + 36 px) і поза зонами інтерфейсу Instagram (верхні 12%, нижні 22% кадру). Кадри, зроблені раніше (зі старим положенням лого), під час збирання відео перекладаються з чистої копії в правильне місце. **Логотип у Reel — шар над відео + фінальна заставка:** у кадри Reel логотип більше не вшивається (і старі кадри з нашим штампом повертаються до чистої копії перед складанням). Під час складання ffmpeg накладає один шар — той самий логотип на всіх сценах, в одному місці, плавна поява 0,6 с. Під логотипом м’яка заокруглена підкладка: світла (білий 82%) для темних і кольорових логотипів, темна (50%) для білих — визначаємо за середньою яскравістю непрозорих пікселів логотипа; назва бізнесу шрифтом бренду (коли немає файлу логотипа) іде на своїй «таблетці». Розміри на кадрі 1080×1920: малий ≤170×110, середній ≤230×150, великий ≤300×200 px (+ поля підкладки); відступ від краю 48 px, згори 12% (смуга Instagram), знизу 22% (підпис і кнопки). Фінальна заставка 2,5 с після сцен: світлий фон (другорядний колір бренду, якщо він світлий, інакше #f6f1ea) або темний (основний колір, якщо темний, інакше #1a1612) — темний лише для білих логотипів; великий логотип (≤620×420), коротка лінія кольору бренду, заклик зі сценарію (до 3 рядків, шрифт бренду), @instagram · сайт. Перехід у заставку — з кольору її фону, без чорного спалаху; маленький логотип на заставці ховається. З заставкою сцени грають повністю, звук (голос / музика / тиша) доповнюється до кінця заставки. Налаштування в Studio → «Звук, субтитри й логотип» → «Логотип»: показувати чи ні, кут, розмір, заставка так / ні (`PATCH /projects/:id/reel-logo {show, corner, size, endCard}`, `projects.reel_logo_json`); поки власник не змінив — беремо з бренд-кіту (логотип на фото, його кут), середній розмір, із заставкою. Якщо відео вже готове, воно одразу перескладається — безкоштовно (кредити не списуються, нічого не генерується). Поки відео немає, телефон у Studio показує, де й якого розміру стане логотип. Проєкт «без бренд-кіту» — без логотипа й заставки; у Studio замість налаштувань одне речення про це. Кнопки кута, розміру й підкладки показуємо лише тоді, коли логотип справді є (файл логотипа або назва бізнесу шрифтом бренду). Якщо є тільки назва без шрифту — підказка додати логотип у бренд-кіт, а лишається тільки «Фінальна заставка: назва бізнесу і заклик». Немає ні логотипа, ні назви — лише підказка, і модель не просимо лишати місце під логотип. Стиль субтитрів «колір бренду» — лише для проєктів з бренд-кітом. **Місце під логотип у кадрах Reel:** коли малюємо кадри Reel, модель отримує точну ділянку, де стане логотип на відео, у відсотках кадру 2:3 — з урахуванням обрізання до 9:16 (≈8% з кожного боку), відступу від краю, смуги Instagram згори (12%) / підпису знизу (22%), вибраного кута й розміру (з налаштувань Reel або бренд-кіту). Приклад для «зліва вгорі, середній»: ≈12% від лівого краю, ≈12% згори, ≈22% ширини × 11% висоти — спокійна рівна ділянка без облич, слів і дрібної текстури, у тоні, на якому читається логотип (кольори логотипа з бренд-кіту). Окремо: «ключова дія — у середині кадру, краї обріжуться». Якщо логотип для Reel вимкнено — ділянку не просимо. Це прохання стоїть одразу після опису сцени (а не в кінці приміток бренд-кіту, де модель його майже ігнорувала) і сформульоване як обов’язкове правило композиції: у ділянці лише рівний фон — гладка стіна, небо, м’яке розмите світло або рівна поверхня — і прямо перелічено, чого там бути не може (квіти, картини, рамки, прапорці, гірлянди, полиці, вікна з деталями, люди, їжа, предмети, слова); головний об’єкт — подалі від цього кута. Підкладка під логотипом тепер перемикається («Підкладка під логотипом», типово увімкнена): для кадрів, намальованих з вільним місцем, її можна вимкнути; якщо кут або розмір змінили вже після кадрів — краще лишити. **Вигляд субтитрів Reel:** субтитри пишемо у форматі ASS (а не SRT зі стилем за замовчуванням) і накладаємо через libass з власною папкою шрифтів. Три стилі (`PATCH /projects/:id/captions-style {style}`, `projects.captions_style`, типово `clean`): «чисті» — Montserrat ExtraBold 86 px, білий з м’якою темною обвідкою й тінню; «на плашці» — Montserrat Bold 72 px, білий на темній напівпрозорій смузі (62%); «колір бренду» — шрифт бренду (свій або Nunito / Montserrat з бренд-кіту, інакше Montserrat ExtraBold) на смузі основного кольору, текст темний або білий — за яскравістю кольору. Розмітка кадру 1080×1920: по центру, поля 90 px, низ тексту на 24% від низу (над підписом і кнопками Instagram), а якщо логотип у нижньому куті — над логотипом. Шрифти Montserrat Bold / ExtraBold (OFL) лежать у `frontend/public/fonts`. Зміна стилю на готовому відео — одразу безкоштовне перескладання; телефон у Studio показує субтитр у вибраному стилі. **Заклик у кінці (CTA) і фінальна заставка:** у редакторі сценарію поле «Заклик у кінці» — до 90 символів, з лічильником «45/90» і підказкою; довший новий текст не зберегти (кнопка неактивна, підказка просить скоротити). Старий довший заклик (написаний AI раніше) лишається як є, доки його не змінять, — підказка каже, що на заставці він буде дрібнішим. Сервер тримає ту саму межу (обрізає по цілому слову), AI просимо писати заклик до 80 символів, переклад — до 90. На заставці заклик показуємо повністю, без «…»: перебираємо розміри 72 → 64 → 56 → 50 → 44 px з дозволеними 3 / 4 / 4 / 5 / 6 рядками й переносимо за реальною шириною тексту в шрифті бренду (ширина рядка до 920 px); якщо текст довгий, логотип піднімається, щоб усе лишилося над нижньою панеллю Instagram. - Телефон-превʼю в Studio показує так само: заголовок поточної сцени вгорі, а внизу — рядок субтитрів, що починається в цій сцені (раніше субтитри бралися за номером сцени й не збігалися з голосом). У редакторі сценарію під полями — коротке пояснення, куди йде текст.
- Ціни не змінились: заголовки — частина збирання відео; змінили напис на готовому Reel — відео перезбирається безкоштовно.
- **Окремі налаштування написів** (`projects.titles_json`, `PATCH /projects/:id/titles`): вкладка «Написи» в картці звуку — показувати чи ні, вигляд («чисті», «на плашці», «колір бренду») і розмір (малий / середній / великий), незалежно від субтитрів (у них своя вкладка й свій вигляд). Типово: показувати, «чисті», середній. Готове відео перезбирається одразу, безкоштовно. У Reel без голосу написів угорі немає — вкладка про це каже.
- **Відео йде в темпі голосу.** Раніше кожна сцена тривала однаково (30 с ÷ кількість сцен), а голос міг бути довшим — кінець обрізався, кадри й заголовки випереджали те, що звучить. Тепер у Reel з голосом кожна сцена починається, коли голос доходить до її слів (за часом слів із розпізнавання; рядок субтитрів знає свою сцену — `cue.scene`; якщо такого часу немає — пропорційно довжині тексту сцени), остання закінчується трохи після голосу, тож відео рівно таке довге, як голос (+ фінальна картка). Рядок субтитрів зникає разом зі своєю сценою. Без голосу — як раніше, рівні сцени.
- **Налаштування Reel з першого кроку.** Картка «Налаштування Reel: голос, субтитри, написи, логотип, музика» видна з самого початку (раніше — лише після сценарію) і відкрита, поки відео не готове; після — згорнута. Стоїть під кнопкою кроку. Вкладки: Голос, Субтитри, Написи, Логотип, Музика. На вкладці «Голос» до запису — вибір голосу зі зразками й «Без голосу»; на самому кроці «Голос» вибір стоїть біля кнопки запису (вкладка тоді відсилає туди). На вкладці «Субтитри» до їх створення — «Без субтитрів». Усе застосовується, коли збирається відео, і змінюється потім безкоштовно.
- «Без голосу» / «Без субтитрів» до кадрів (і навіть до ідеї) лише запам’ятовують вибір (`voice_off` / `captions_off`), крок проєкту не змінюється; запис голосу чи субтитри на їхньому кроці знімають позначку, як і раніше. Увімкнути голос до кроку «Голос» — без підтвердження з ціною (платиться на кроці).
- **Вимкнути голос на готовому Reel:** на вкладці «Голос» картки звуку — «Вимкнути голос» (раніше «Без голосу» було лише на кроці перед записом). Відео перезбирається саме, без AI і безкоштовно: субтитрами стають написи сцен, заголовків угорі немає. Запис голосу з його субтитрами зберігаємо (7 днів після останньої зміни), тож поки він є, кнопка — «Повернути голос · безкоштовно» (`voiceTakeSaved` у відповіді); коли запису вже немає — «Додати голос» з ціною.
- Поточний голос тепер зберігається як запис перед будь-яким його прибиранням (вимкнення, зміна тексту голосу, повернення іншої ідеї чи сценарію, перегенерація) — також для голосів, записаних до збереження записів. Записи, збережені до вибору голосу (ключ лише за текстом), теж знаходяться, якщо були зроблені тим самим голосом.

**Подарунковий сертифікат (v1.77).** Новий вид картинки «Сертифікат» (`image_intent = certificate`, гілка `feature/image-certificate`).
- **Як працює:** AI малює лише оформлення — рамку, мотив зі справи бізнесу, кольори бренду, спокійний порожній центр, без жодних літер (окремий запит у `stillPicturePrompt`; логотип і контакти на картинку не ставимо). Усі слова друкує студія: логотип або назва бізнесу, заголовок (типово «Подарунковий сертифікат» / «Gift certificate», можна змінити), ім’я отримувача (без слова «Для»), що дарують (послуга або сума), «Дійсний до», «Код», примітка (наприклад, запис за телефоном), адреса й контакти з бренд-кіту. Текст у кольорі бренду, а якщо колір світлий (жовтий, пастельний) — темний, щоб читався. Текст лягає прямо на згенероване оформлення, по центру його спокійного поля, з ледь помітним світлим висвітленням (без білої плашки); тип картинки визначається за вмістом файлу (AI віддає PNG, збережений як `still-1.jpg` — через це спершу був чорний фон). Велике превʼю зліва показує сертифікат вибраної людини з усіма словами.
- **Формат:** A5 горизонтально (√2:1, `image_format = a5`, вибирається сам); файл для друку — PNG 2480×1748 (300 dpi) і PDF A5 (одна сторінка, без сторонніх бібліотек).
- **Необов’язкові поля:** без імені на сертифікаті — лише лінія, щоб вписати від руки; код можна вимкнути («Друкувати код») — тоді коду немає ні на сертифікаті, ні в назві файлу (`certificate_json.codes`). Назва файлу: ім’я (або «сертифікат»), що дарують (до 40 знаків), код і мова — наприклад «сертифікат-Free cocktail-англ.pdf».
- **Що дарують і додатковий рядок:** «Що дарують» — великим жирним (наприклад COMPLIMENTARY COCKTAIL), під ним «Додатковий рядок (дрібніше)» — звичайним шрифтом (Enjoy a cocktail on us!); обидва перекладаються з вибором мови, великі літери лишаються.
- **Положення й розмір тексту:** у блоці «Сертифікати» — превʼю з рамкою навколо тексту: перетягнути (мишкою чи пальцем) — пересунути, куточок — змінити розмір; повзунок «Розмір тексту» (50–160 %) і «Як було». Однаково для всіх сертифікатів оформлення, зберігається само (`certificate_json.layout` — центр блоку й масштаб); текст не виходить за межі сторінки.
- **Термін:** «Дійсний з» і «Дійсний до» — обидва необов’язкові; друкується «Дійсний з 01.11.2026 до 31.12.2026», «Дійсний з …» або «Дійсний до …» (англійською «Valid from … to …» / «Valid from …» / «Valid until …»), залежно від того, які дати вписані.
- **Скільки людей:** до 50 сертифікатів з одного оформлення; код генерується сам (8 знаків без 0/O і 1/I, як «NQRB-U8HH») або свій; кожен — «PDF для друку» і «PNG»; перегляд показує збережений сертифікат вибраної людини. Мова службових слів — українська чи англійська: перемикає лише те, що друкує студія («Подарунковий сертифікат» / «Gift certificate», «Дійсний до / Valid until», «Код / Code»); стандартний заголовок перемикається з мовою, свій — лишається; слова власника друкуються як написано; вибір мови («Мова сертифіката: Українська / English») одним натисканням перекладає й слова власника — заголовок (якщо свій), «Що дарують» і примітку — безкоштовно; повторний переклад тексту, що вже цією мовою, не дає помилки (`POST /projects/:id/certificate/translate`, gpt-4o-mini); імена, дати, коди й суми (£50) не змінюються.
- **Ціни:** ідея (5) і оформлення (8) — як у звичайної картинки; збереження, перегляди й файли для кожної людини — безкоштовно, без AI. «Змінити щось на картинці» доступне для оформлення; новий формат, переклад і логотип для сертифіката сховані (вони не потрібні).
- **API:** `PATCH /projects/:id/certificate` (заголовок, примітка, мова, люди; `projects.certificate_json`), `GET /projects/:id/certificate/:index?format=pdf|png|preview`.

**Перенесення акаунта на інший сервер (v1.78).** Щоб перенести свій акаунт з локальної бази на продакшн, не чіпаючи інших людей там.
- **Експорт:** `npx tsx scripts/export-account.ts you@example.com [файл.tar.gz]` (у `backend`) — один `.tar.gz` (за замовчуванням у «Завантаження»): `account.json` з рядками акаунта, бренд-кіта, усіх проєктів, їхніх версій, відгуків і історії генерацій, плюс `media/<projectId>/…` і файли бренд-кіта. Кредити й план не переносяться.
- **Імпорт:** сторінка Database (`/app/admin`, лише власник) → «Import an account». Файл іде частинами по 20 МБ (`POST /admin/import/:uploadId/part/:n`, ≤ 25 МБ кожна, разом ≤ 2 ГБ, по черзі; частина 0 починає нове завантаження й прибирає незавершене), потім `POST /admin/import/:uploadId/finish`. Частини розпаковуються одразу, як приходять (gzip + власне читання tar у Node, без системного `tar`): записуються лише звичайні файли `account.json`, `media/<projectId>/…`, `media/brand/account/…` — без `..`, посилань і macOS-файлів `._*`. Рядки додаються в одній транзакції лише в колонки, які є на цьому сервері. Помилка показує крок і код; «The server disk is full.» — якщо на томі не вистачає місця.
- **Чий акаунт:** якщо на сервері вже є акаунт з тією ж поштою — проєкти й бренд-кіт додаються до нього (пароль, ім’я, кредити й план залишаються серверні; бренд-кіт замінюється імпортованим). Якщо немає — створюється з тим самим ім’ям, поштою й паролем, планом Free і стартовими кредитами. Проєкт з тим самим id замінюється (повторний імпорт безпечний).
- **Місце на диску:** сам архів на сервері не зберігається — потрібно лише місце під файли акаунта (≈ розмір папок `media` проєктів); розпаковані файли переносяться (не копіюються) у `DATA_DIR/media`, тимчасова папка `DATA_DIR/import` видаляється й після помилки.

**Логотип на сертифікаті (v1.81, гілка `feature/certificate-logo`).** У блоці «Положення, шрифт і колір тексту» — «Логотип»: «З бренд-кіту» (логотип з бренд-кіту — ваш файл, тож його можна взяти й на сертифікат, зроблений без бренду; кнопка вимкнена лише коли в кіті немає лого. Сертифікат без бренду, де логотип ще не вибирали, лишається без лого — як друкувався досі), «Свій файл» (PNG / JPG / WebP до 2 МБ, лише для цього сертифіката, працює й без бренд-кіту; `media/<projectId>/cert-logo.img`, тип за байтами, не видаляється 7-денним прибиранням) і «Без логотипа». Свій файл можна замінити або прибрати (`POST` / `DELETE /projects/:id/certificate/logo`). Логотип друкується над заголовком у блоці тексту — рухається й масштабується разом з ним; рамка на превʼю враховує його висоту (`certificate_json.logo = brand | own | none`; у відповіді `ownLogo`, `brandLogo`). Назва бізнесу замість логотипа — лише для «З бренд-кіту», коли в кіті немає лого.
- **Місце під логотип у дизайні:** промпт сертифіката більше не бере загальний бренд-блок (там «пиши назву правильно» і «лиши куток під лого» — через це AI малював назву бізнесу). Тепер з бренду лише кольори, настрій і сфера; прямо сказано не малювати назву й логотип, а центр — разом з верхньою частиною, де ми друкуємо лого, — без емблем, монограм і табличок. Перевірено: з лого й усіма полями блок займає ≈ 64% висоти сторінки при порожньому центрі ≈ 67%; на старих дизайнах з намальованою назвою блок можна посунути або зменшити.
- «Як у бренді» в шрифтах знову міняє лише заголовок (ім’я й подарунок — жирний Montserrat, як до v1.80).
- **Логотип окремо від тексту:** на превʼю в лого своя рамка (над рамкою тексту). Натиснути на лого — і тягнути його куди завгодно (мишкою, пальцем, стрілками), за куточок — розмір (30–300%). З першим рухом лого відділяється від тексту (`certificate_json.logoLayout = { x, y, scale }`, центр у частках сторінки; розмір — від вписаного у 520×170 логотипа), а текст лишається на місці: сервер зсуває блок на половину місця лого (`LOGO_ROOM`), рамка тексту стає нижчою. «Лого — як було (над заголовком)» повертає його в блок, текст — назад. У відповіді `logoBoxes` — де лого кожного сертифіката, для рамки.
- **Свій вигляд у кожного варіанта картинки:** положення тексту й лого, розмір, шрифт, кольори й вибір логотипа зберігаються для вибраного варіанта дизайну (`certificate_json.looks[<visuals version id>] = { layout, style, logo, logoLayout }`); інші варіанти не змінюються. На широкому екрані (від 1181 px, висота від 680 px) телефон із Reel закріплений угорі під час прокрутки — сцени й панель кроку гортаються, відео завжди видно; у перегляді кроку — від 901 px. На вужчих екранах, де сцени йдуть під телефоном, і на мобільному — без закріплення. Картинки й запрошення поки без змін. **Перегляд готового кроку Reel** (клік на крок угорі): панель перегляду займає широку колонку, телефон — вузьку, список сцен під телефоном ховається (він дублював би сценарій); на телефоні під час перегляду картинка прихована. Шапка: маленька «← До кроку …», заголовок «Сценарій — що вийшло», одне речення-підказка. Сценарій: рядок інструментів («Редагувати сценарій» + «Перекласти все: англійською / українською»), сцени рядками — мітка часу («0 с»), напис на екрані жирним, текст голосу під ним; «Заклик у кінці» — окремою рамкою з підписом. Субтитри — так само рядками з міткою «0.0–3.0 с». Кадри: під кожним — «Перезняти · 8» (кнопка закриває перегляд і відкриває звичайне «Чому не підійшло?», бо воно живе в панелі кроку); клік по кадру показує його в телефоні, поки відео немає; підказка — що невдалий кадр перезнімається окремо за 8 кредитів, а готове відео оновиться саме. Старі варіанти ідеї / сценарію — згорнутий список «Варіанти сценарію (N)»: поточний зверху з міткою «Зараз», далі від новіших; у рядку мітка, перший рядок тексту й маленька «Взяти» (замість сітки великих карток; так само й для ідеї картинок). **Навігація кроками (хлібні крихти):** рядок кроків угорі Studio (Ідея · Сценарій · Кадри · Голос · Субтитри · Створити) — пройдені кроки й поточний є кнопками, майбутні — підписи. Натиснути пройдений крок = подивитися, що на ньому вийшло (ідея, сценарій зі сценами й часом, кадри мініатюрами, голос із плеєром, субтитри зі списком), там же список версій ідеї / сценарію з поверненням старішої; нічого не генерується й не списується. Поточний крок лишається обведеним, переглядуваний позначено окремо. Назад — «← До кроку «…»» у панелі огляду, кнопка поточного кроку або «← Попередній крок: …» під заголовком поточного кроку. **Вибрана картинка завжди на виду:** на широкому екрані (> 900 px) картинка в Studio «липка» — лишається видимою, поки прокручуються правки праворуч; під нею підпис «Вибрано: Варіант N · портрет 4:5. Усі зміни нижче — для цієї картинки.» (під час ручного розміщення лого — «Розміщуєте логотип…»). На вузьких екранах — як було, щоб картинка не закривала кнопки. **Ручне розміщення лого** (Studio → «Розмістити логотип вручну», також на брендових картинках з автоматичним лого): картинка показується без нашого лого (`GET /projects/:id/logo/base`), поверх — файл лого (`GET /projects/:id/logo/mark`, або назва бізнесу шрифтом) у пунктирній рамці; його можна перетягнути мишкою, змінити розмір за куточок або повзунком «Розмір» (4–80% ширини), стрілки зсувають, Shift+стрілки — розмір; рамка не виходить за межі картинки. Початок — збережене місце або автоматичний кут (`GET /projects/:id/logo/layout` → `box` {x, y, w} у частках картинки, `markRatio`, `pictureRatio`). «Зберегти розміщення» = `POST /projects/:id/logo` з `box`: безкоштовно, без AI, ставимо рівно туди на картинку моделі, нова версія; у `visuals[].logoBox` + найближчий кут у `logoCorner`. Після AI-правок лого повертається в той самий `box`, а моделі кажемо цю точну зону. Неправильний box → 400 «Put the logo inside the picture.» **Модель лого ніколи не бачить:** файл лого їй не передається, промпт просить не малювати лого. Для правки мови / слів (`keepStill`) картинки з нашим лого моделі йде картинка моделі **без** лого, а після правки ми ставимо лого назад у той самий кут (`visuals[].logoCorner`, з чистою копією) — тож лого не перемальовується моделлю і завжди прибирається безкоштовно. **Вибір у списку версій:** натискання на картинку робить її вибраною й поточною (restore без підтвердження, без AI); підпис «Вибрано» стоїть на ній, «Видалити» — на інших. **Видалення картинок зі списку версій:** під кожною, крім поточної, — «Видалити»; над списком (коли версій > 2) — «Залишити лише поточну картинку»; обидва з підтвердженням, без повернення. Якщо видаляється картинка моделі, від якої зроблені версії з лого, вони не ламаються: версія, що збігається з картинкою моделі, займає її місце (успадковує `generation_id`), а решта отримують власну чисту копію — «Прибрати логотип» і далі повертає правильну картинку. Версії в списку впорядковані за часом і порядком створення (кілька за одну секунду не плутаються). Підказки зв’язують обидва місця: у Brand Kit (плитка лого, перемикач, вибір кута) сказано, що лого можна додати й пізніше на готову картинку в Studio; у Studio — що кут за замовчуванням і автоматичне лого на всіх нових картинках налаштовуються в Brand Kit (з посиланням). Disclaimer: назва / лого / фото — його; людей лише за згодою. **Збереження:** лого й фото зберігаються одразу після вибору файлу й **не затирають** поля, які ще вводяться; решта — кнопкою Save. Є рядок «Є зміни, які ще не збережені», кнопка стає «Зберегти зміни», браузер питає підтвердження при закритті з незбереженим. Після Save: нові ідеї й картинки візьмуть зміни, вже зроблені проєкти лишаються як є. Learned-картка рахує всі готові проєкти (пости й Reel).

**Формат картинки (куди публікуємо).** Для Image Post на Create є вибір «Куди публікуватимете?» (поле `projects.image_format`, API `imageFormat`): **square** 1:1 (стрічка Instagram / Facebook), **portrait** 4:5 (більше місця в стрічці), **portrait34** 3:4 (класична форма фото в Instagram, трохи ширша за 4:5), **story** 9:16 (Stories, обкладинка Reel, TikTok), **wide** 1.91:1 (пост або посилання у Facebook). Дефолт: photo → square, флаєри (invite / info / offer) → portrait. Проєкти, створені до цього, лишаються як були (photo 1:1, флаєр 2:3, у API `tall`). **Модель одразу малює потрібну форму, нічого не обрізаємо.** `gpt-image-2` і новіші (зокрема `gpt-image-2.5-sunburst`) приймають довільний `size` (кратний 16, до 3:1), тому просимо точні розміри: square 1024×1024, portrait 1024×1280 (4:5), portrait34 1152×1536 (3:4), story 864×1536 (9:16), wide 1536×800 (≈1.91:1). Це працює і в `images.generate`, і в `images.edit` (приклади до брифу, «Та сама картинка», «Змінити слова»). У промпт іде рядок `Canvas: …` із формою й вимогою тримати слова та головний об’єкт щонайменше 6% від країв. **Старі моделі:** якщо в `OPENAI_IMAGE_MODEL` вручну задати `gpt-image-1` (вміє лише 1:1, 2:3, 3:2), малюємо найближчу форму й лише тоді підрізаємо ffmpeg до формату (центрально; розмір файлу перевіряється, готові точні картинки не чіпаємо). Для правки слів на такій моделі картинку перед `images.edit` розширюємо розмитими краями, а потім підрізаємо назад. Лого й контактний рядок ставляться після цього, у кутах фінальної картинки. Прев’ю в Studio, порівняння takes і Download JPG мають ту саму пропорцію. Reel цього не стосується (завжди 9:16).

**Приклади до брифу (example refs).** Окремо від Brand Kit, працює і з `use_brand=0`. До **3** картинок (сервер приймає PNG/JPG до 2 MB, перевірка за байтами, SVG ні; **браузер сам готує файл** (тип визначає за першими байтами, не за назвою — картинка з інтернету часто WebP під назвою .jpg): будь-яку картинку, яку він відкриває — велике фото з телефона, WebP, HEIC у Safari, SVG — зменшує до 2048 px і перетворює на JPG до 2 MB; лого в Brand Kit — на PNG, щоб зберегти прозорість; `frontend/src/lib/imageUpload.ts`). Приклади з Create зберігаються одразу після створення проєкту; якщо якийсь не зберігся, Studio каже про це в блоці прикладів («не збереглися — додайте тут ще раз»), а не мовчить додаються на Create (вантажаться одразу після створення проєкту) і в Studio біля поля Бриф (додати / прибрати, зберігається одразу). Файли лежать у каталозі проєкту як `example-{1|2|3}.{png|jpg}`, віддаються лише власнику, видаляються разом із проєктом і акаунтом, не чистяться 7-денним прибиранням проміжних файлів. API: `POST /projects/:id/refs` (`{image}` data URL; ліміт 3), `GET /projects/:id/refs/:slot`, `DELETE /projects/:id/refs/:slot`; `refs: [{id,url}]` є в `serializeProject`. У кроці **Pictures** (Reel-кадри, photo, флаєри) вони йдуть першими файлами в `images.edit` (`gpt-image`) разом із рядком у промпті: узяти предмет, стиль, композицію й настрій з прикладу, зробити нову картинку; букви, лого й водяні знаки з прикладу не копіювати, якщо бриф цих слів не просить; на флаєрі приклад може стати фото-зоною. Після них — фото з Brand Kit (на флаєрах їх, як і раніше, нема). Додатково credits не беруться. «Та сама картинка» / «Змінити слова» (`keepStill`) приклади **не** шлють — редагується картинка на екрані. Якщо `images.edit` не вдався, fallback `images.generate` іде без прикладів. Приклад вмикається з наступного запуску Pictures.

**Мова Idea.** Текст Idea (`title`, `hook`, `concept`, `audience`, `visualDirection`) пишеться мовою інтерфейсу (`Accept-Language` запиту: `uk` → українська, інакше англійська), незалежно від мови брифу. Для invite об’єкт `invite` (імена, дати, місце, програма) лишається дослівно як у брифі, без перекладу. Мова слів на самій картинці — окремо (`pictureLanguage`).

**Billing.** 4 плани (поточний виділено, `yourPlan`), 3 пакети з £, таблиця кроків 150 / 13. **Choose / Buy сховані**, поки немає `STRIPE_SECRET_KEY`. Лог generation **не показуємо** (`SHOW_AI_COST_LOG=false`). Внизу — лише посилання на **Account** (видалення акаунта переїхало туди). Ціни **FROZEN**.

**Account** (`/app/account`, відкривається кліком по імені в сайдбарі). Секції: **План і кредити** (план, баланс, «з нами з …», лінк на Billing) · **Профіль** (ім’я; пошта — зміна лише з поточним паролем, 409 якщо зайнята) · **Пароль** (поточний + новий двічі, мін. 6 символів, новий ≠ поточний; після зміни всі інші пристрої розлогінені, цей отримує свіжий токен) · **Ваші дані** (`GET /auth/export` → `auteur-export.json`: профіль, текст бренд-кіту, бріфи, idea / script / voice / captions, історія credits; **без** картинок, лого, фото й відео — їх качають з проєкту) · **Сесії** (Sign out; **Sign out on all devices** — підтвердження, потім токени всіх пристроїв стають недійсними) · **Delete account** (поле пароля + confirm; без правильного пароля — 403). Кнопки Save неактивні, поки нема змін. Помилки пароля — 403 `Current password is incorrect.` (не 401, щоб не розлогінювати).

**Library.** Список проєктів: промпт, тип, статус, credits, дата. Відкрити в студії, **скопіювати бриф**, **видалити** (`DELETE /projects/:id` — файли й версії; кредити не повертаються, confirm у UI). Якщо термін вийшов — статус `expired` і підказка, що Create знову платний. Перед витісненням через ліміт плану — попередження, не тихе зникнення.

### 4.2 Тема і мобільна версія

**Тема.** Світла й темна. Перемикач ☀ / ☾ у сайдбарі, на лендингу, auth і preview. Вибір у `localStorage` (`auteur.theme`: `light` / `dark`); поки власник не обирав — тема пристрою (`prefers-color-scheme`), і вона слідує за системою. Маленький inline-скрипт у `index.html` ставить `data-theme` на `<html>` до React (без спалаху). Кольори інтерфейсу — CSS-токени (`--bg`, `--surface*`, `--ink`, `--muted`, `--line`, `--accent`, `--hover*`); у світлій темі `--accent-2` темніший (читається як текст), кнопка `.btn` темна, шум слабший. **Не міняються:** чорна сцена плеєра, підписи на кадрі, білий фон під лого й фото, прев’ю Brand Kit у кольорах власника — це полотно, а не інтерфейс. Нові кольори — лише токенами, без жорстких `#hex` у компонентах.

**Мобільна версія** (web, адаптивно; до 960 px). Сайдбар → липка верхня панель: логотип, кредити, кнопка ☰ (випадне меню: тема, EN/УК, ім’я + план, Sign out; закривається при переході). Знизу фіксована панель із 4 вкладок: Create · Library · Brand kit · Credits, з урахуванням `safe-area-inset-bottom` (`viewport-fit=cover`). Основний вміст має запас під панель. Заголовки 34 px, компактніші prompt-stage і панелі, прев’ю Reel ≤ 320 px, цілі натискання ~44 px, hover-підйом вимкнено на сенсорних екранах. Нативні застосунки — поза v1 (§2.2).

**Доступність.** З клавіатури видно фокус: `:focus-visible` — кільце `--accent-2` на посиланнях, кнопках, полях і селектах (для мишки не з’являється); прихований `input type=file` підсвічує кнопку, що його відкриває. `outline: none` у стилях не використовуємо. Найменший шрифт — 13 px (підказки, підписи полів, описи у вибірках). `prefers-reduced-motion: reduce` вимикає анімації (Ken Burns на прев’ю, hover-підйом карток, переходи).

### 5.3 Політика файлів (до S3)

Проміжні артефакти дешеві в генерації відносно готового ролика; **готовий mp4 або stills — те, за що користувач заплатив.** Не можна ставити їм однаковий короткий TTL.

| Артефакт | TTL | Чому |
| --- | --- | --- |
| `voice.mp3`, `scene-*.jpg`, `captions.srt`, записи голосу, шрифти субтитрів | **7 днів** після `updated_at` (музика `music.m4a` — 90 днів, разом із відео) | можна зібрати mp4 знову з credits, місце на диску |
| `reel.mp4` | **90 днів** після Create, або одразу після успішного S3 | зберігання дешеве; регенерація = 55 cr + залежності |
| `still-*.jpg` | **90 днів** (як mp4) | Download Image Post = файл OpenAI |
| Після S3 | локальна копія mp4 можна стерти; рядок проєкту й `output_url` лишаються | |

Ліміт **готових mp4 на диску** — від плану. **TTL 90 днів для mp4 однаковий для Free і Business** — свідомо проста політика; довший архів Business з’явиться разом із S3, не як окремий локальний TTL.

| План | Готових mp4 на диску |
| --- | --- |
| Free | 10 |
| Creator | 30 |
| Pro | 60 |
| Business | 120 |

Витіснення найстарішого mp4 — **тільки якщо** користувач на ліміті **і** підтвердив попередження в UI («найстаріший Reel буде знято з диска; завантажте, якщо ще потрібен»). Без підтвердження Create на ліміті → 409 з текстом, не тихе видалення. Рядок у Library лишається (`expired`, якщо файлу немає).

На екрані Create / Ready обов’язковий copy:

> Download this Reel now. We keep the mp4 for 90 days. Voice and frames may be cleared after 7 days. Recreating after that uses credits again.

### 5.4 Паралельний рендер (відомий ліміт бети)

Один Node-процес, ffmpeg як child process. **Максимум 2 одночасні Create.** Третій і далі чекають у черзі процесу (не 503 одразу). Закриття вкладки **не скасовує** рендер: робота живе на бекенді. Credits за Create резервуються **до** ffmpeg (як інші кроки). Для закритої бети 5–10 людей цього достатньо. Окрема черга (Bull/Redis) — **після бети**, не блокер інвайтів.

**Метрика №1 бети (рендер):** у `ai_generations.meta_json` / колонки `started_at`, `finished_at`, `duration_ms` для кожного кроку; для render ще `queueWaitMs`, `encodeMs`. Якщо середній `queueWaitMs` > 30 с — винести рендер з API-процесу до публічного запуску. Окремо дивитись TTS vs OpenAI Images vs ffmpeg: захлин може бути в послідовних OpenAI, не в ffmpeg.

**idea**

```json
{
  "title": "string",
  "hook": "string",
  "concept": "string",
  "audience": "string",
  "visualDirection": "string"
}
```

Для `image_intent=invite` Idea також пише `invite` у відповіді → `invite_json`. На JPG це не впливає.

Для **Image Post** в `idea_json` ще є кадр, який власник підтверджує перед Pictures:

```json
{
  "shot": {
    "subject": "string",
    "place": "string",
    "angle": "string",
    "people": "string",
    "mood": "string",
    "words": "string — точні слова на картинці або none",
    "summary": "одне речення"
  },
  "shotConfirmed": false
}
```

Idea для картинок пишеться з `temperature 0.4` (менше фантазії, ближче до брифу). Нова Idea завжди скидає `shotConfirmed`. Старі ідеї без `shot` отримують кадр з `visualDirection`.

`POST /projects/:id/shot` (JWT, 0 credits, без AI): `{ "shot": { subject, place, angle, people, mood, words, summary } }` — зберегти поля, як власник їх написав (без «у кадрі» і «одним реченням» → 400), `shotConfirmed` скидається; `{ "confirm": true }` — підтвердити. Можна обидва разом. Перша `POST /steps/visuals` для Image Post без `shotConfirmed` → **400** `shot_unconfirmed`, credits не списуються. Перезйомка, коли картинка вже є, не вимагає повторного підтвердження.

`stillPicturePrompt`: спершу «зніми саме цю сцену, не вигадуй інше місце / пейзаж», далі підтверджений кадр рядками (`Shot / In the frame / Place / Camera / People / Light and mood / Words`), далі бриф як факти, далі бренд (для фото — режим `photo`: колір і настрій, без назви й лого на кадрі). Для фото без слів у кадрі — «Photograph only, no letters».

**script**

```json
{
  "durationSec": 30,
  "cta": "string",
  "scenes": [
    {
      "id": 1,
      "time": "0–3s",
      "onScreen": "string",
      "voiceover": "string",
      "visualPrompt": "string"
    }
  ]
}
```

**visuals** — масив `{ sceneId, imageUrl, prompt, placeholder? }`. `placeholder: true` = OpenAI відхилив кадр (ключ при цьому вже є). Без ключа крок Visuals не стартує.

**voice_json (інструкція, не медіа).** Назва поля в API можна показувати як `voiceDirection`, щоб ні розробник, ні UI не вважали крок «озвучено».

```json
{
  "voicePreset": "warm_british_female",
  "script": "повний текст для TTS, зліплений зі сцен",
  "notes": "Natural pace. Pause after the hook. Never sound like an ad read."
}
```

У коді крок `voice`: direction JSON (`voicePreset` + `script` + `notes`) → TTS → `audio_url`. Поки файлу немає, крок **не done**.

**captions** — `{ cues: [{ start, end, text }] }` у секундах.

MVP-вирівнювання: **не word-level**. Cues будуються зі сцен скрипта (частки 30 с або фактична тривалість аудіо, пропорційно). Спалити в mp4 через ffmpeg `subtitles=`. Це свідомий компроміс: OpenAI `tts-1` не дає таймкодів слів. Точне «слово = кадр» — post-MVP (ElevenLabs / whisper alignment), не блокер першого файлу і не блокер бети, якщо текст читається.

### 6.9.1 Brand Kit Learning — правило-базований v1 (не ML)

Не тренувати модель. Агрегувати accepted vs rejected + причину в `brand_kits.learned_summary_json` і підмішувати в system prompt як текстові підказки.

**Тригер.** Після кожного **третього** `ready`/`expired` проєкту цього Brand Kit — фонова джоба. Не рахувати живцем на кожен звичайний запит. Поки < 3 ready — не рахувати (шум). `POST /brand/learning/reset` стирає `learned_summary_json` і **одразу** викликає той самий перерахунок з наявної історії (`force`); якщо ready < 3 — картка лишається порожньою, UI це каже. `other` + note **не** парсити в v1; зберігати для ручного перегляду.

| visuals | Частотні слова `prompt` accepted vs rejected | `"visualNotes": "warm natural light, avoid stock-photo look"` |
| voice | `voicePreset` ≥2 ready поспіль без reject | `"preferredVoice": "warm_british_female"` |

```json
{
  "generatedAt": "2026-09-23T12:00:00Z",
  "basedOnProjects": 4,
  "avoid": ["too_salesy"],
  "preferredPace": "concise",
  "preferredVoice": "warm_british_female",

```

### 6.12 Публічний preview-лінк (не шедулер, не соцмережа)

Власник хоче показати Reel партнеру / бариста / дружині **до** викладу. Це не публікація.

- `POST /projects/:id/share` (JWT) — токен + TTL 7 днів; повторний Share оновлює expiry.
- `preview_token` — **криптографічно випадковий, 32 байти** (`crypto.randomBytes(32).toString('hex')`, 64 hex). Не UUID v1 і не обрізаний UUID. Публічний, без auth — ентропія обов’язкова.
- Сторінка `/preview/:token` (без логіну). Медіа: `GET /share/:token/file` і `/share/:token/image/:sceneId`.
- `GET /projects/:id/preview?token=` — той самий JSON без auth.
- Не постійний Download URL і не S3. Після TTL — 404. Кнопка *Share a preview* у студії **схована** (`SHOW_SHARE_AND_PUBLISH`), ендпоінт лишається.

Порівняння версій Idea/Script/**Visuals**: `GET` проєкту віддає **усі** знімки кроку в `versions`; `POST /projects/:id/versions/{idea|script|visuals}/:versionId/restore` ставить обрану `accepted=1`, **0 credits**. Idea/script — каскад як regenerate. Visuals — за `{ sceneId }` відкочує один кадр з файлового знімка `still-{sceneId}-{versionId}.jpg` (mp4 скидається). Image / Post показує всі takes; `GET /projects/:id/image/:sceneId/versions/:versionId` віддає знімок.

### 7.2 Регенерація (UX і ціна)

Власник малого бізнесу, якому не зайшов голос або кадр, **не** має єдиним виходом починати новий проєкт — це вбиває retention.

| Дія | Credits | Ефект |
| --- | --- | --- |
| `POST /steps/:step` повторно, крок уже done, **без** `regenerate` | 0 | повернути поточний проєкт, **AI не викликати** |
| `POST /steps/:step` з `{ "regenerate": true }` | ціна кроку; з 4-ї спроби **2×** | новий виклик AI/TTS/ffmpeg, перезапис артефакту |
| `POST /steps/visuals` з `{ "regenerate": true, "sceneId": N }` | **8**; з 4-ї Visuals-спроби **16** | лише цей кадр; mp4 скидається |
| `POST .../versions/{idea\|script\|visuals}/:id/restore` | **0** | повернути вже оплачену версію; visuals — по `sceneId`, файл зі знімка |
| Недостатньо credits | 402 | лишити версію або докупити credits |
| Провайдер викликаний, крок упав | списані | refund немає — запит уже коштував нам грошей |

Каскад після успішної регенерації (наступні кроки знову **не done**, їхні файли/JSON чистяться):

| Перегенеровано | Скидається |
| --- | --- |
| idea | script, visuals, voice+audio, captions, mp4 |
| script | visuals, voice+audio, captions, mp4 |
| visuals | mp4 (повний набір або один `sceneId`; captions лишаються) |
| voice | **captions і mp4** (новий TTS = інша тривалість `voice.mp3`; старі cues, підігнані під попередній файл, роз’їдуться вже на scene-level) |
| captions | mp4 |
| render | лише новий mp4 |

Не сподобалось згенероване — **не** новий проєкт з нуля:

1. Поправити бриф у студії (`PATCH` prompt) → **Regenerate idea** (5 cr, каскад).
2. Ідея ок, текст ні — **Regenerate script** (10 cr).
3. Один кадр — **8 cr**.
4. Голос / субтитри / mp4 — кнопка кроку за тією ж ціною; наступні кроки скидаються.

Кнопка в панелі: *Not this {step}? Try again · N credits*. Після 3 спроб: *Keep this, or another try · 2×*. Confirm на extra.

Користувач завжди може **лишити** поточне (безкоштовно) або **заплатити ще раз**. Новий проєкт — опція, не тупик.

### 7.3 Часткова відмова Visuals

Крок Visuals = пачка кадрів. Повна ціна 40 = 5 × 8. **Не списувати 40, якщо цінність неповна.**

Поріг успіху: **≥ ceil(n × 3/5)** живих кадрів (для 5 сцен = **3**). Нижче порогу — крок `failed`; якщо провайдер уже викликаний, резерв **не** повертається.

| Результат | Крок | Credits | Що бачить користувач |
| --- | --- | --- | --- |
| Живих кадрів нижче порогу (ключ є) | `failed` | **зарезервовані 40 лишаються** (вендор уже виставлений) | *We couldn’t generate enough frames (k of n). Try a simpler description.* |
| Живих ≥ порогу, частина placeholder | `succeeded` | **live × 8** (не 40) | Бейдж на кожному placeholder **до Voice** |
| Усі n кадрів живі | `succeeded` | **n × 8** (5 сцен = 40) | Звичайний прев’ю |
| Немає `OPENAI_API_KEY` | не стартує | 0 | **503** *We can’t make pictures right now. Try again in a few minutes.* (причина в логу). Градієнт-прев’ю **не** пишеться |

5xx від OpenAI Images: **один автоматичний retry** на кадр, потім як відмова (placeholder / поріг). 4xx policy — без retry, одразу placeholder.

Успішні API-виклики в пачці, яка впала по порогу, **вже оплачені credits** (резерв не повертається). `actual_cost_gbp` у логу `failed`.

Один кадр після succeeded: **8 credits** за `sceneId`.

**Image / Post (n = 1).** Поріг = **1** (все або нічого; `ceil(1 × 3/5) = 1`). Не екстраполювати «3 з 5» на один кадр.

Перед `failed` на єдиному кадрі: **один додатковий авто-retry** `images.generate` (не лише 5xx). Якщо й він порожній — тоді `failed`.

### 9.4 Unit-економіка: підписка vs пакети (явно)

На заморожених цифрах орієнтовно:

| Канал | £ / Reel (якщо Reel = 150 cr) | Роль |
| --- | --- | --- |
| Підписки | ≈ £0.94–1.50 / Reel | **залучення**: дешевий вхід, звичка |
| Пакети | ≈ £3.00–3.75 / Reel | **прибуток**: хто вичерпав ліміт |

Це не випадковість прайсу, а стратегія: підписка веде в продукт, докупівля credits несе маржу. Після розморозки зберегти цей розрив (пакети дорожчі за 1 Reel, ніж підписка), якщо unit-економіка з TTS+рендером це дозволяє. Якщо собівартість mp4 з’їсть підписку — спочатку підняти credits/ціну підписки, не зрівнювати пакети вниз.

Стратегія §9.4 **неперевірювана**, поки рахуємо лише `actual_cost_gbp` за Reel. Рентабельність бізнесу = CAC / LTV / churn. Нижче — **робочі гіпотези**, не факти. Їх треба підтвердити або вбити на закритій беті та першому ads-тесті. Без цього «підписка = залучення» лишається внутрішньою логікою.

### 9.5 Бізнес-економіка (гіпотези, щоб §9.4 було чим перевірити)

Цифри **не для інвестора як факт**. Статус: HYPOTHESIS, поруч із FROZEN на прайсі.

| Метрика | Гіпотеза v1 | Як перевірити |
| --- | --- | --- |
| **CAC** власника малого бізнесу (UK, Instagram/Facebook) | Закрита бета: **£0** (інвайт). Платний тест: **£25–40 за користувача, який дійшов до першого mp4** (не за клік і не за signup) | Одна кампанія ≥ £300 spend **після** бети; рахувати cost / completed Reel, не / landing visit |
| **Reels / місяць** на активного | **4** (раз на тиждень — реалістичний «регулярний контент» кав’ярні/салону; не 30) | Медіана готових mp4 на юзера за 28 днів у беті та після запуску |
| **Тривалість підписки** | **2 місяці** медіана, якщо < 2 Reel/міс; **≥ 4 місяці**, якщо ≥ 4 Reel/міс | Stripe `current_period_end` + churn після webhook |
| **LTV (грубо, Creator)** | £9.99 × 3 міс ≈ **£30** до відтоку. Якщо CAC £30 — підписка **сама себе не окупає**; маржа має сидіти в пакетах і в тому, що Free не рекламуємо в ads | Порівняти CAC з LTV після ≥ 40 платних спроб |
| **Churn-сигнал** | Немає другого проєкту за 14 днів після першого mp4 → з високою ймовірністю не продовжить (зв’язок із §11.11) | Той самий когортний звіт |

Правило перевірки §9.4: якщо після ads-тесту **CAC ≥ LTV підписки** і пакети не докуповують — стратегія «підписка дешева для звички» провалена; не масштабувати ads, підняти Creator або звузити канал до інвайту/партнерств. Якщо CAC £25 і людина робить 4 Reel/міс на Creator — стратегія жива.

Собівартість генерації (§9.0) лишається окремим інваріантом: credits кроку ≥ 3× `actual_cost_gbp`. Це **маржа на Reel**, не заміна CAC/LTV.

### 9.6 Собівартість успішного Reel (не лише готових файлів)

`actual_cost_gbp` на один `status=ready` проєкт **недостатньо**. У `GET /billing/credits` → `economics`:

- text / image / tts / render;
- **failed** (виклики, що впали після провайдера);
- **retries** (повторні виклики того ж кроку);
- **total**;
- `readyReels`;
- `costPerReadyReelGbp` = total / ready (failed і regenerate входять у чисельник).

Поле `economics` є в `GET /billing/credits`. На екрані Credits **не показуємо** (`SHOW_AI_COST_LOG=false`). 150 credits — внутрішня одиниця, не «ціна Reel для людини».

### 10.1 Контент, бренди, privacy (блокер публічного лендінгу, не бети)

Закрита бета 5–10 інвайтів може йти без публічної privacy policy. **Етап «Публічний лендінг» (§1.5 / §12) заборонений**, доки немає:

1. **Content policy / відмова моделі.** TTS або Visuals нижче порогу §7.3 — `failed`, людський текст. Credits **не** повертаються, якщо провайдер уже викликаний. Частковий успіх ≥ порогу — `live × 8`, placeholder з бейджем **до Voice**.
2. **Чужі знаки.** Brand Kit — відповідальність користувача: лого/назва, які він вводить, вважаються його. Короткий disclaimer на Brand і на signup (не юридичний трактат). Перевірка товарних знаків автоматично — **не MVP**.
3. **GDPR / UK GDPR.** Перед публічним запуском: privacy policy, підстава обробки, **self-service `DELETE /auth/account`**. Перед стиранням рядків: якщо є `stripe_subscription_id` — **`subscriptions.cancel` у Stripe**, потім видалення проєктів/медіа/brand/credits/email. Інакше Stripe продовжить списувати картку. Ручне видалення адміном — запас для бети 5–10, не заміна ендпоінта.

## 11. Критерії приймання MVP

**Функціональні (без них продукт не демоїти як Reel):**

1. Новий користувач реєструється і бачить 400 credits.
2. Можна створити Reel з промптом і пройти всі 6 кроків → **на диску/за запитом є відтворюваний mp4 ~30 с 9:16** (не лише прев’ю в DOM).
3. Крок Voice не вважається done без аудіофайла (`audio_url`).
4. Після повного шляху баланс = 250 (при вартості 150 і старті 400), у Library статус ready **і** файл.
5. Повторний Idea **без** `regenerate` не списує 5 credits і **не викликає AI**; **з** `regenerate` — списує і каскадить; 4-та спроба Idea — **10 credits (2×)**, не 429 (§7.2).
6. Video / Ad / Social post не створюють проєкт. **Image / Post створює** (13 cr; `GET …/image/:sceneId` = `still-1.jpg` з OpenAI). Invite / info / offer: Same picture in EN/UK — 8 cr, той самий JPG-layout.
7. Brand Kit зберігається і впливає на Idea; якщо `use_brand=1` — кольори/ніша в тексті, фото залу/людини/товару в `images.edit`, лого на кадр лише шаром якщо `logo_on_photos`. Лого і фото не обов’язкові.
8. Credits: плани, пакети, таблиця 150/13, поточний план виділено. Лог generation у API є, у UI **схований**. Checkout без Stripe не відкривається.
9. Idea / Script / Captions без ключа дають preview-JSON. **Visuals без `OPENAI_API_KEY` — 503 з людським текстом.** Voice без ключа: `say` або тиша. **Бета і зовнішнє демо — ключ + TTS + ffmpeg**, не тихий wav.
10. `GET /health` = 200. `GET /projects/:id/file` віддає mp4, коли файл є.

**Утримання (інакше «успіх MVP» суб’єктивний; фазу постів не починати):**

11. Не менше **30% користувачів, які закінчили перший Reel (є mp4), створюють другий проєкт протягом 14 днів.**
12. Вибірка:
    - **n = 20** з першим файлом — **слабкий сигнал**. На цьому розмірі **не** приймати go/no-go лише по відсотку (6 людей; 1–2 випадковості = ±15–20 п.п.). Обов’язково **≥ 5 якісних розмов** (що не зайшло в голосі/кадрі/ціні). Рішення «продовжувати бету / різати фічу» — число **плюс** фідбек.
    - **Хард-гейт наступного формату** (пост/реклама): §11.11 виконано на вибірці **≥ 40** користувачів з готовим першим mp4 — не на реєстраціях без файлу, не на n=10 закритої бети.

13. Регенерація Voice або Visuals доступна в UI і тарифікується; єдиний шлях «новий проєкт» **не** є прийнятим UX.
14. Питання *Would you publish this Reel/post?* і кнопка *Share a preview* у UI **сховані** до потреби бети; ендпоінти лишаються. Download не залежить від відповіді. **Publishability** — окремий KPI від «файл зібрався».

## 12. Дорожня карта

Документ дисциплінує себе: **нові формати чекають retention-гейт n≥40**. Нижче — що вже в скоупі бети vs що за гейтом.

**Уже зараз (без нового формату; підсилює retention і publishability):**

1. Brand Kit learning (§6.9.1) — **є**.
2. Feedback на рівні кроку (§6.11) — **є**.
3. Публічний preview-лінк (§6.12) — **є** (показати партнеру, не викласти).
4. Порівняння двох останніх Idea/Script/**Visuals** і restore без credits — **є**.

**Етапи доступу (як було):** закрита бета 5–10 → чекпоінт собівартості → privacy/delete → публічний лендінг → CAC-тест → гейт §11.11.

**Після §11.11 на n≥40, за цінністю (не хронологією старого списку):**

1. Image Post уже один JPG з OpenAI на kind. Далі — лише якщо треба кілька файлів на одну програму івенту, не «зібрати постер шаром».
2. Word-level captions (ElevenLabs alignment) — раніше YouTube, бо ріже publishability.
3. **Реклама**, потім **Відео** — дві кнопки, **§2.3**. Рух у кадрі — **§12.1**, не нова картка.
4. S3, upload лого, YouTube / презентації.

**Не в скоупі зараз:** шедулер публікації. Окрема дешева перевірка пізніше — **нагадування створити** наступний Reel (email/push), не шедулер викладу; атакує гіпотезу 4 Reels/міс (§9.5).

### 12.1 Майбутнє: рух у кадрі й реклама (після бети)

Власник малого бізнесу має зараз **короткий ролик зі статичних картинок**. Далі той самий продукт має вміти віддати **той самий ~30-секундний Reel, але з рухом у кадрі**: людина / руки / товар / легкий наїзд — якщо власник захоче «маленьке відео з рухаючими героями».

Це **не** новий формат і **не** кнопка **Відео** на Create. Кнопка «Відео» — довший ролик на сайт / YouTube (**§2.3**). Рух — еволюція збірки в уже існуючому **Короткому відео**.

#### 12.1.1 Що є зараз і що буде

| Зараз (бета / MVP) | Після бети, якщо сторіборда мало |
| --- | --- |
| OpenAI-кадр на сцену → ffmpeg тримає still + `tts-1` + SRT → `reel.mp4` ~30 с 9:16 | Той самий кадр іде в **один** image-to-video → кліп 5–8 с на сцену → ffmpeg склеює кліпи + той самий голос і SRT |
| Власник пише одне речення на Create | Той самий Create, ті самі 6 кроків. Нової кнопки «Animate / Kling» **немає**. Картка **Відео** — окремий формат (§2.3), не вмикач руху |
| «Герой» = людина в кадрі салону / кав’ярні / залу (майстер, гість, руки, товар) | Той самий герой **рухається** в межах уже згенерованої сцени. Не кролик у піжамі, не 2–5 хв казки |

**Рухаючі герої в Auteur** = персонажі бізнесу в рекламному сенсі (майстер фарбує, бариста ставить чашку, клієнт усміхається). Не авторський мультсеріал і не «придумай свого героя».

#### 12.1.2 Коли підключати (і коли ні)

Не підключати жоден image-to-video **до** закритої бети (5–10) і чекпоінту собівартості на 20–50 реальних mp4.

| Коли | Що | Як |
| --- | --- | --- |
| Закрита бета | Нічого з цього параграфа | Кадри OpenAI + `tts-1` + ffmpeg. Виміряти, чи сторіборда взагалі публікують. |
| Після 20–50 mp4, якщо «просто картинки» ріжуть publishability | **Один** image-to-video | Слот `encodeReel`: `still-{sceneId}.jpg` **або** `clip-{sceneId}.mp4`. Голос і SRT свої. Не нова кнопка на Create. |
| Після гейту §11.11 (n≥40) | Кнопки **Реклама**, потім **Відео** | **§2.3**. Той самий стек, різні скелети й файл. |
| Ніколи як ядро | CapCut / Canva / Premiere на фініші | Текст, лого, музика — у нашому Create. Інакше продукт знову шар над редактором. |
| Ніколи як ядро v1 | Дитячий мультконвеєр | Midjourney / Leonardo / Canva + Kling/Runway/Dreamina + ElevenLabs-діалоги + CapCut. Інша ніша, інші кредити, ламає обіцянку «ми зробимо решту». |

Публічний i2v **заборонений**, поки не перераховані `CREDIT_COSTS.render` і/або Visuals: рух дорожчий за still. Інакше Creator £9.99 не витримує собівартість.

#### 12.1.3 Вендор: хто оживляє кадр

Користувач **ніколи** не вибирає вендора. Імена моделей (Kling, Runway, Veo, Seedance) **не** на Create і не в Studio. Зміна API — лише адаптер у бекенді. Якщо ціна впаде — змінити адаптер, не екран.

| Роль | Вендор | Навіщо так |
| --- | --- | --- |
| **Перший і єдиний на старті** | **Kling image-to-video** з уже згенерованого `still` | Auteur уже має фото сцени й Brand Kit на ньому. Треба оживити кадр (пара, рука, товар, наїзд), не малювати нове кіно з тексту. |
| Запасний адаптер | **Runway** | Якщо Kling API або оплата для UK незручні. Той самий контракт: still → 5–8 с кліп. |
| Не першим | **Veo** | Тягне свій звук. У Auteur голос уже свій (`tts-1`). Подвійне аудіо ламає Voice + captions. |
| Пізніше, лише реклама | **Seedance** (або аналог з кількома референсами) | Коли з’явиться Advertisement і треба товар + обличчя з 2–3 референсів. Не для першого i2v у Reel. |
| Не підключати | Роутер «обери Kling / Runway / Veo» | Це маркетплейс моделей. Суперечить §1. |

Кліп **5–8 секунд на одну сцену**, не 30 секунд одним шматком і не 2–5-хвилинний фільм. 4–6 сцен × 5–8 с ≈ той самий ~30 с Reel.

**Kling уміє text-to-video** (промпт → ролик без картинки; у 3.0 ще multi-shot і свій звук). Це **не** перший шлях Auteur.

| | Image-to-video (беремо) | Text-to-video (не першим) |
| --- | --- | --- |
| Вхід | наш `still` + короткий motion-промпт системи | лише текст |
| Brand Kit / обличчя / інтер’єр | тримаються з кадру, який власник уже бачив і може restore | модель малює заново; кадри сцен роз’їдуться |
| Крок Visuals | лишається: порівняти, regenerate однієї сцени | треба прибрати або зробити фейковим |
| Звук | Kling `audio: off`, голос свій `tts-1` | у Kling є native audio — **вимкнути**; інакше подвійне аудіо як у Veo |
| Коли розглянути | Коротке відео після бети | пізніше кнопка **Відео** (§2.3), і лише якщо без ключового still не обійтись. Власник усе одно не обирає режим |

Не показувати на Create «з картинки / з промпту». Один адаптер у бекенді.

#### 12.1.4 Як це лягає в пайплайн (контракт для коду, не робити зараз)

1. Visuals як зараз: OpenAI малює `still-{sceneId}.jpg`.
2. Render (або внутрішній підкрок після Visuals, **не** окремий крок на Create): для кожної live-сцени бекенд викликає Kling з кадром + коротким motion-промптом (з Idea/Script: «рука ставить чашку», «легкий наїзд»). Відповідь — `clip-{sceneId}.mp4` 5–8 с.
3. `encodeReel` підставляє кліп замість still; якщо i2v упав — fallback на still, проєкт не падає цілком (як часткові Visuals).
4. Voice і captions **не** змінюються: `voice.mp3` + SRT, підгін під тривалість голосу як зараз.
5. Власник бачить той самий Studio: Make → файл. Без чіпа «Kling», без «завантаж у CapCut».

Motion-промпт пише система, не користувач. Опційний короткий hint у брифі («щоб майстер рухав руками») — ок; окреме поле «опиши анімацію» — ні.

### 12.2 Майбутнє: картинка з шарів — розібрати й переставити частини (не робимо зараз)

**Задача.** Власник хоче готову картинку «розібрати на частини» — заголовок, дату, адресу, логотип, фото, окремі предмети — і переставляти, збільшувати, ховати їх, як у Canva. Зараз є лише ручне розміщення нашого лого (`logoBox`, §4 Studio) і AI-правка «змінити щось» (8 кредитів, не точна).

**Два підходи (оцінка — тиждень-два роботи кожен):**

| | A. Розібрати вже готову картинку | B. Одразу робити картинку з шарів (рекомендовано для флаєрів) |
| --- | --- | --- |
| Як | (1) знайти частини: текст — розпізнаванням тексту з межами блоків; предмети / люди — модель виділення об’єктів (Segment Anything тощо, через сторонній сервіс ≈ $0.002–0.01 за картинку); (2) вирізати кожну частину шаром з прозорим фоном; (3) домалювати фон там, звідки частину забрали (`images.edit` з маскою, ≈ 8 кредитів); (4) редактор шарів у Studio; (5) збирати фінальний файл на сервері (resvg / ffmpeg, як лого) | AI малює лише фото / фон **без тексту**; заголовок, дата, адреса, лого — наші окремі шари (текст, шрифт і кольори з Brand Kit), фінальний файл збираємо самі |
| Плюси | Працює з тим, що вже намальовано, «дизайнерський» вигляд AI лишається | Текст завжди чіткий і редагується безкоштовно, без AI; якість передбачувана; шари рухаються, змінюють розмір, колір, текст |
| Мінуси | Погані краї (волосся, прозоре, тіні); перенесений предмет не підлаштовує світло й тінь; вирізаний текст — картинка, розмивається при збільшенні й не редагується як текст; дорожче (виділення + домальовування) | Зникає момент, коли AI сам гарно вписує написи у фото; треба шаблони розкладки під формати (1:1, 4:5, 3:4, 9:16, 1.91:1) |
| Що спільного | Редактор шарів у Studio (перетягнути, розмір, сховати, порядок), збереження як нова версія, `logoBox`-логіка для кожного шару, фінальне складання на сервері | |

**Порада.** Нові флаєри — з шарів (B); для готових картинок — одна простіша дія «вирізати й перемістити один предмет» на тих самих виділенні й домальовуванні фону (частина A). Перед стартом: перерахувати кредити (виділення + домальовування), вирішити, чи лишаємо режим «AI малює текст сам» поряд із шарами.

**Статус:** відкладено, у бету не входить. Почати лише за окремим рішенням власника продукту.

## 15. Що лишається відкритим (не стек)

TTS, ffmpeg, TTL, регенерація, часткові Visuals, self-service delete, ліміт ffmpeg, idempotency кроків, publishability, economics на billing — **закриті в коді / ТЗ**. Нижче чекпоінти:

1. Перерахунок `CREDIT_COSTS` / планів після **20–50 роликів закритої бети** за **cost per successful Reel** (§9.6), не лише сума succeeded.
2. Чи scene-level captions достатні, чи після бети брати ElevenLabs заради word-timestamps.
3. Чи гіпотеза CAC £25–40 жива після першого ads-тесту (§9.5) — якщо ні, не масштабувати рекламу.
4. Точна дата публічного лендінгу — після бети **і** §10.1 (privacy/content + delete), не навпаки.
5. Чи черга з 2 ffmpeg тримає бету; якщо середній `queueWaitMs` > 30 с — винести рендер з API-процесу до публічного запуску.
6. Три питання долі продукту: **чи публікують Reel**; **чи є другий за 14 днів (≥30%, n≥40)**; **чи додатна unit-економіка з failures+retries**. Нові формати — тільки якщо всі три не провалені.
7. Чи після 20–50 mp4 сторіборда достатньо, чи вмикати Kling (§12.1). Якщо вмикати — нова собівартість i2v **до** публічного руху; адаптер можна змінити на Runway без зміни Create.

## 16. Технічні ризики MVP (P0 / P1)

Не переписувати продуктову логіку. Це контракт для розробки до закритої бети.

**P0 — у бета-коді або жорстко до публічних платних:**

1. Idempotency AI/credits (`Idempotency-Key`) — **є**.
2. Резерв credits до провайдера — **є**.
3. Статус проєкту `draft | generating | ready | expired`; крок `running` у `ai_generations` — **є**.
4. Render не скасовується закриттям вкладки; лог `queueWaitMs` / `encodeMs` — **є**.
5. TTL-job проміжних 7д / mp4 90д — **є**.
6. JWT expiry (14д) + 401 не з мережі; відкликання токенів через `token_version` (зміна пароля, «вийти скрізь») — **є**.
7. Authorization на project/file/audio — **є**.
8. Concurrent той самий крок — 409 — **є**.
9. Stripe webhook idempotency — **до публічних підписок**, не блокер інвайт-бети без Stripe.
10. Rate limit 20 POST steps / хв / юзер — **є**.

**P1 — одразу після стабільного mp4, раніше нових форматів:**

11. Brand learning з `project_step_versions` + `step_feedback` + `learned_summary_json` — **є** (§6.9.1, §6.11).
12. Beta dashboard: queue wait, cost per ready Reel, publishability %.
13. S3.
14. Окрема черга рендеру, якщо §5.4 червона.

**P2:** ElevenLabs, Remotion, mobile, scheduler, YouTube, team, voice clone, batch, agency, crypto — заборонені, доки §11.11 на n≥40.

Три питання, без яких не додавати формати:

1. Люди отримують Reel, **який хочуть викласти** (publishability), не лише коректний mp4.
2. ≥30% з першим mp4 роблять другий проєкт за 14 днів (n≥40 для хард-гейту).
3. Собівартість **доставленого** Reel (TTS + кадри + render + failed + regenerate) лишає маржу.
